# NyaHaX'93 ランキングリセット

NyaHaX'93 のランキング（`NX93.SCR`）は上位 10 件しか持たないため、強い一人が上位を
占め続けると他の人の記録が入らなくなる。日付が変わるたび（または週が変わるたび）に、
各人の最高記録 1 件だけを残して配布時のランキングへ差し戻し、席を空ける。
消える記録は平文 2 枚（歴代トップ 30 と、ユーザごとの最高記録）へ移すので、
98 の上で `TYPE RANK30.TXT` と打てばそのまま読める。

この README は**使い方**を述べる。中を変えるなら `docs/` を読むこと:

| | |
| --- | --- |
| [`docs/SPEC.md`](docs/SPEC.md) | **契約。** 引数・画面出力・ファイル形式・不変条件・エラー分類・受け入れ基準 |
| [`docs/DECISIONS.md`](docs/DECISIONS.md) | **なぜこの形なのか。** 決定 1〜25 と、それぞれ採らなかった案 |
| [`docs/TEST-DESIGN.md`](docs/TEST-DESIGN.md) | **試験設計。** ケースごとのオラクルと、何を殺すかの実測 |
| [`tests/README.md`](tests/README.md) | 試験の走らせ方とフィクスチャの作り直し方 |

試験は仕様から起こしてあり、実装から逆算していない。`RANK.C` を変えて赤くなったら、
期待値より先に仕様を見ること。

## 構成

| ファイル | 置き場所 | 役割 |
| --- | --- | --- |
| `dist/GAME.BAT` | 98: `A:\GAME\NX93\` | 入口。`RANK /D` → `NX93` の順に起動する |
| `dist/RANK.EXE` | 98: `A:\GAME\NX93\` | 更新プログラム。`build.sh` が Mac 上で作る |
| `dist/RANK.C` | 98: `A:\GAME\NX93\` | その原本。98 上の `QCL RANK.C` に戻すための保険 |
| `build.sh` | Mac のみ | `RANK.C` → `dist/RANK.EXE`。ia16-elf-gcc を Docker 経由で呼ぶ |
| `.built-from` | Mac のみ | `dist/RANK.EXE` が由来する `RANK.C` の sha256 |
| `tests/` | Mac のみ | Mac 側の回帰テスト。98 には送らない |

98 側で動くのは `GAME.BAT` と `RANK.EXE` の 2 つ。`RANK.C` も一緒に送るが、98 上で
使うのは QuickC へ戻すときだけ。

## 引数

```
RANK /D     日付が変わったらリセットする（GAME.BAT の出荷時の指定）
RANK /W     週が変わったら（月曜 00:00 を跨いだら）リセットする
RANK        引数なしは /W と同じ
RANK /d     小文字も同義。/w も同じ
```

- **判定は経過時間ではなく暦の境界。** 日曜 23:59 に遊んで月曜 00:01 に遊べば、
  2 分しか経っていなくても `/W` はリセットする。逆に月曜から日曜 23:59 までは
  6 日 23 時間 59 分でもリセットしない。
- **どちらの規則で走ったかはどこにも記録しない。** 出所は引数だけなので、
  `/D` と `/W` はどちら向きにでも切り替えられる。走った規則は画面の
  `daily` / `weekly` の字句が伝える。
- 上記 4 綴り以外（`/X`・`FOO`・`-D`・`/DD`・空文字列）や引数 2 個以上は、
  **何も開かず・何も書かず**に usage を出して終了コード 1。黙って既定へ落とすと
  打ち間違いが毎日リセットに化けるため。

更新頻度を変える作業は `GAME.BAT` の `RANK` の行を 1 つ書き換えるだけで、
そのことは `GAME.BAT` 自身の `rem` にも書いてある。

## 導入手順

### 1. Mac で RANK.EXE を作る

```sh
mise run build:nx93rank
```

Docker で ia16-elf-gcc 6.3.0 を呼び、small モデルの MZ 実行形式を `dist/RANK.EXE`
へ書く。イメージはダイジェストで固定してあるので、`:latest` が動いても結果は変わらない。
MZ ヘッダが無ければビルドは失敗する（`-mcmodel` が効かずに tiny が出て、拡張子だけ
`.EXE` のフラットイメージを掴まされるのを防ぐため）。静的領域（`.data + .bss`）が
32 KiB を超えた場合もビルドは失敗する。small モデルの 64 KB データセグメントに
表 2 枚とスタックを同居させるため、ここは機械で押さえてある。

`dist/RANK.EXE` はリポジトリにコミットしてあるので、`RANK.C` を触っていなければこの
手順は飛ばせる。触ったのに作り直し忘れた場合は `mise run verify` が
`verify:nx93rank-binary` で落ちる（sha256 の照合。Docker は要らない）。

### 2. Mac から 98 へ送る

SD カードを Mac にマウントした状態で（手順は README.md の 3 章）:

```sh
./98hdd send nx93rank/dist /GAME/NX93
```

`dist/` の 3 ファイルだけが `A:\GAME\NX93\` に入る。`.bat` と `.c` は拡張子
ホワイトリストに載っているので Shift-JIS + CR+LF へ自動変換され、`.exe` は載っていない
ので `[BIN]` としてそのままコピーされる（SPEC.md §5.5）。

### 3. 遊ぶ

```
A:\GAME\NX93>GAME
```

`RANK.EXE` が日付の変わり目にランキングを整理し、そのあと `NX93.EXE` が起動する。
`GAME.COM` や `GAME.EXE` をこのディレクトリに置かないこと。MS-DOS のコマンド解決順は
COM → EXE → BAT なので、`GAME.BAT` が実行されなくなる。

## QuickC に戻すとき（保険）

ia16-elf-gcc の newlib と QuickC のランタイムは別物なので、実機で `RANK.EXE` が
おかしな挙動をしたら 98 上でビルドし直して切り分ける。

```
A:\>CD \GAME\NX93
A:\GAME\NX93>QCL RANK.C
```

`QCL` のパスと `INCLUDE` / `LIB` は `AUTOEXEC.BAT` が設定済み（SPEC.md §7.1）。
メモリモデルは既定の small でよい。浮動小数点は使っていないので数値ライブラリは
引き込まれない。`RANK.OBJ` が残るが消してよい。Mac から送った `RANK.EXE` は
上書きされる。

この保険があるために `RANK.C` には制約が残っている（後述の「制約」）。やめるなら
`dist/RANK.C` を送るのをやめ、ASCII 限定の検査（`tests/run.sh` の S1）も外せる。

## 4 枚のファイル

すべて `RANK.EXE` 自身のあるディレクトリ、実機では `A:\GAME\NX93\`。

| 本名 | 役割 | 大きさ |
| --- | --- | --- |
| `NX93.SCR` | ゲームが読む 10 行。`RANK.EXE` は行のバイト列を加工せずに書き戻す | 10 行 |
| `RANK30.TXT` | 歴代トップ 30。`NX93.SCR` と同じ行形式の平文 | 最大 30 行 |
| `RANKWHO.TXT` | ユーザごとの最高記録。1 人 1 行、同じく平文 | 最大 100 行 |
| `NX93.TXT` | 状態だけ。最終リセット時刻を持つ 45 バイト固定の JSON | 45 バイト |

`RANK30.TXT` と `RANKWHO.TXT` は `NX93.SCR` と同じ行形式なので、98 の上で
`TYPE RANK30.TXT` と打てばそのまま読める。どちらも不在はエラーではなく 0 行の表で、
初めての起動が自分で作る。

`NX93.TXT` の中身はこれだけで、リセットしない起動では 1 バイトも書き換わらない。

```json
{
  "lastUpdate": "2026-10-26T02:00:00"
}
```

このほか、更新中に落ちたときだけ `RANKTMP.*`（一時ファイル 4 本）と
`RANKOLD.*`（差し替え前の退避 4 本）が現れることがある。正常に終わった起動は
どちらも残さない。例外は「差し替えの rename と戻しの rename が両方失敗した」場合で、
そのときは対象 1 枚が退避名の下に全バイト残り、画面がその名前と戻し方を名指す。

### リセットの中身

1. `RANK30.TXT` に、`NX93.SCR` から消える行を足す。行のバイト列が完全一致する行は
   1 件に畳む。31 件目になったら最下位が落ちる（歴代 30 の床を割るのが歴代 30）。
2. `RANKWHO.TXT` に同じ行を足す。同じ人の行は**真に高いスコアのときだけ**差し替える。
   101 人目になったら最下位の 1 行が落ち、落ちた行を画面に出す（黙って消さない）。
3. `NX93.SCR` を組み直す。鍵ごとの最高 1 件と配布時の 10 行からスコア降順で上位 10 件。
4. `NX93.TXT` に今の時刻を書く。

順序は 1 → 2 → 3 → 4 で固定。`NX93.SCR` は唯一「失うもの」なので、その記録が 1・2 に
載った後でなければ消えない。4 が最後なので、途中で落ちても次回起動が同じリセットを
やり直す。1〜3 は何度流しても結果が変わらない（行一致の重複除去と鍵ごとの最大値）ので、
やり直しは害にならない。

### 同じ人かどうかの判定

名前欄の後ろにマークを付ける人がいる。マークは同じ人の印なので識別に使わない。
鍵は「前後の空白を落とす → 末尾の『ASCII かつ非英数字』を落とす → 空になったら
落とす前へ戻す → `a-z` を大文字へ畳む」で作る。

| 名前欄 | 鍵 | |
| --- | --- | --- |
| `omzn`, `OMZN`, `OMZN@@@@`, `omzn++++`, `omzn-` | `OMZN` | 全部同じ人 |
| `omzn-2` | `OMZN-2` | 末尾が英数字なので何も落ちない。`omzn` とは別人 |
| `TARO2` | `TARO2` | `TARO` とは別人 |
| `@@@@` | `@@@@` | 落とすと空になるので元のまま |
| Shift-JIS の名前 | 末尾まで保存 | 0x80 以上のバイトに当たったら落とすのをやめる |

最後の 1 行は必須の規則で、最適化ではない。Shift-JIS の名前は 0x80 以上のバイトで
終わるので、素朴に「非英数字を落とす」と日本語名が空の鍵に潰れ、別人どうしが全員
同一人物になる。

## 動作

| 状態 | 動作 | 終了コード |
| --- | --- | --- |
| 暦の境界を跨いでいない | 何もしない（規則の字句と経過日数を出す） | 0 |
| 境界を跨いだ | リセット | 0 |
| `NX93.TXT` が無い（初回） | リセット | 0 |
| `RANKWHO.TXT` が 100 人で埋まり 1 行落ちた | リセット。落ちた行を画面に出す | 0 |
| 退避名に残っていた旧バイトを片付けた | リセット。片付ける前に画面に 1 行出す | 0 |
| 未知・過剰な引数 | 何もしない（usage を出す） | 1 |
| ディレクトリ名が長すぎる | 何もしない | 1 |
| 時計が読めない | 何もしない | 1 |
| `NX93.TXT` の `lastUpdate` が読めない | 何もしない | 1 |
| `lastUpdate` が未来（時計が巻き戻った） | 何もしない | 1 |
| `NX93.SCR` に読めない行がある / 11 行以上ある | 何もしない | 1 |
| `RANK30.TXT` に読めない行がある / 31 行以上ある | 何もしない | 1 |
| `RANKWHO.TXT` に読めない行・101 行以上・同じ人が 2 行 | 何もしない | 1 |
| 4 枚のどれかが読み取り専用 | 何もしない | 1 |
| `NX93.TXT` が状態ファイルでも旧台帳でもない | 何もしない | 1 |
| 移行しようとしたら `NX93OLD.TXT` が既にある | 何もしない | 1 |
| 旧台帳が文法違反で読み切れない | 何もしない | 1 |
| 書き込みの途中で失敗した | 失敗した段より前の枚だけ新しい | 1 |

終了コード 1 のときは `GAME.BAT` がメッセージを出して `PAUSE` する。最後の 1 行以外は
**4 枚とも 1 バイトも書き換わらない。** 画面のメッセージは、どのファイルが実際に
差し替わってどれが差し替わっていないかを必ず述べる。そのままキーを押せばゲームは起動する。

終了コードは 0 と 1 しかない。`errorlevel` は「以上」の比較なので、2 を足すと分岐の
順を誤ったときにエラーと混ざる。ユーザ上限超過と退避の片付けは画面 1 行だけで、
終了コードは 0 のままである。

## 旧形式からの移行

週次だけだった時代の `RANK.EXE` は、消した記録を `NX93.TXT` の `backups` 配列へ
積んでいた。新しい `RANK.EXE` はこれを読んで取り込む。

1. 新しい `RANK.EXE` と `GAME.BAT` を送り、`GAME` と打つ。
2. **最初に暦の境界を跨いだ起動**で移行が走る。それまでは旧 `NX93.TXT` はそのまま
   残り、`lastUpdate` を読むためにだけ使われる（リセットしない起動は何も書かない）。
3. `backups[].ranking[]` の全行が `RANK30.TXT` と `RANKWHO.TXT` へ流れる。
   取り込みはメモリの中で完結するので、**1 行でも読めなければディスクに 1 バイトも
   書かずに終了コード 1** になる。直してから再実行すればやり直せる。
4. 成功すると旧 `NX93.TXT` は `NX93OLD.TXT` へ退避され、**消されない。**
   新しい `NX93.TXT` は 45 バイトの状態ファイルになる。
5. 二度目は走らない。新しい `NX93.TXT` は `"backups"` を含まないので発火条件が
   成立しない。`NX93OLD.TXT` は以後読みも書きもされない。

`NX93OLD.TXT` が既にある状態で移行が走ろうとしたら、**何も書かずに終了コード 1**。
過去の退避を黙って上書きして失わないため。やり直したいときは `NX93OLD.TXT` を
手で改名・移動してから実行する（取り込みは冪等なので、再取り込みそのものは無害）。

取り込み後の見え方: 実機の `NX93.SCR` は `OMZN`（327400）と `OMZN@@@@`（299370）を
別人として持っているが、新しい鍵の規則では同じ人なので、リセット後の `NX93.SCR` に
残る実記録は 327400 の 1 行だけになる。消えた行は `RANK30.TXT` に全部入る。

Mac に吸い上げるときは `98hdd pull` で `hdd/game/nx93/` に入る（カードを定義して
いるなら `hdd/<カード名>/game/nx93/`）。`.txt` は変換対象なので UTF-8 + LF になる。

## 記録を手で戻したいとき

`RANK30.TXT` と `RANKWHO.TXT` の行は `NX93.SCR` の 1 行そのものなので、戻したい行を
`NX93.SCR` へ書き写せばよい。守ること:

- ちょうど 10 行。各行は CR+LF で終わり、最終行も CR+LF。末尾に 0x1A を置かない。
- 行のバイト列は変えない。スコアの桁数だけが可変で、残りは固定幅である。
- 11 行以上や読めない行があると、次の起動が終了コード 1 で止まる（表はそのまま）。

`RANK30.TXT` / `RANKWHO.TXT` 自身を手で編集してもよいが、`RANKWHO.TXT` は
**1 人 1 行**が約束なので、同じ人の行を 2 本書くと次の起動が止まる。
新しい鍵の規則では `OMZN` と `OMZN@@@@` が同じ人なので、これは手編集で実際に起こる。

止まったときは `RANKWHO.TXT` を消せば次の起動が作り直す。ただし**作り直しの出所は
`NX93.SCR` だけ**なので、`RANKWHO.TXT` だけが持っていた行は失われる。普通に溜まった行は
`RANK30.TXT` にも同じ行が入っている（どちらの表も `NX93.SCR` の行を候補に取るため）が、
**手で `RANKWHO.TXT` にだけ足した行は歴代表のどこにも無い。消す前に写しておくこと。**
画面のメッセージも同じことを言う。

リセットそのものをやり直させたいときは `NX93.TXT` を消す。次の起動が初回とみなして
リセットする。

## Mac 側のテスト

```sh
nx93rank/tests/run.sh        # 53 ケース（週次からの回帰）
nx93rank/tests/run-daily.sh  # 85 ケース（毎日更新・引数・移行・故障注入）
```

`run.sh` は `mise run verify` からも走る。`run-daily.sh` の接続はユーザー作業で、
手順は `tests/README.md` にスニペットを置いてある。

実機の DOS では試せないもの（コンパイラのコード生成、DOS のランタイム挙動、
`errorlevel` 分岐、`NX93.EXE` 側の読み取り互換）は範囲外で、実機確認に委ねている。
何を試験していないかは `tests/README.md` に書いてある。

クロスコンパイルができても、ここは縮まない。`clang` で回す 138 ケースが保証するのは
RANK.C の論理で、`ia16-elf-gcc` が通ることが保証するのは C89 適合とリンクまで。
newlib の `fopen` がバイナリモードで CR+LF を素通しするか、`rename` / `remove` が
DOS でどう振る舞うかは、実機で一度動かすまで未検証のまま。

## 制約

- `RANK.C` のメッセージは ASCII に限る。Shift-JIS の 2 バイト目に `0x5C` を含む字
  （ソ・表・能 等）を QuickC がエスケープとして解釈するため。日本語を出したい箇所は
  `GAME.BAT` の `ECHO` に置く。クロスコンパイルだけなら不要な制約で、QuickC を保険に
  残しているあいだだけ効く。
- DOS 判定は `RANK.C` の `RANK_DOS` 一箇所に集約してある。QuickC は `MSDOS` を、
  ia16-elf-gcc は `__MSDOS__` と `_DOS` を定義し、どれも共通ではない。外すとパスの
  区切りが `/` のまま警告なしで通る（`tests/run.sh` の S8・S9 が固定している）。
- `int` は 98 では 16 ビット。スコアは `long` で、暦の計算も全部 `long`。旧台帳の
  取り込みは行を数えない（4 万行の台帳が 16 ビットで溢れるのを、数えないことで消す）。
- ヒープは使わない。表は静的領域に置く（DOS の既定スタックは約 2 KB で、
  `RANKWHO.TXT` 用の表 1 個でそれを 4 倍超える）。旧台帳はストリームで読み、
  全体をメモリに載せない。
- `RANK.EXE` は**カレントではなく自分の居場所**（`argv[0]` のディレクトリ）の
  4 枚を読む。DOSSHELL から起動してもゲーム本体と同じ表を見る。
  DOS 2.x は `argv[0]` を空で渡すので、その場合だけカレントに落ちる。
