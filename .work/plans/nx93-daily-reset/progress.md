## 2026-10-22（続き・architect）

- architect が実装計画を返した（`impl-plan.md`）。T1〜T14。RANK.C は 1 ファイルのまま
  約 2,150 行（1.6 倍）、`rank_run` を読み相 → 書き相の 2 相に分解、実装は緑を保つ
  3 フェーズに分割。既存試験は 61 → 53 ケース（旧台帳 writer の削除で 8 件が消える）。
- **計画の欠陥を 1 件見つけて直した。** 計画は「`*_RENAME` 注入で差し替え rename と
  復帰 rename の両方を失敗させる」としていた。POSIX では復帰 rename が必ず成功するので
  E15（STRANDED）が観測できない、という理由は正しい。しかしこれをやると**仕様の
  E14「差し替え失敗・復帰成功」が観測不能**になる。復帰が成功する経路は 3 段コミットが
  存在する理由そのもので、既存 I-18 が張っている唯一の網。計画は「E14 は `*_COMMIT` が
  担う」としていたが、`*_COMMIT` は `rank_commit` に入る前に戻るのでロールバックを
  一度も通らない。注入点を `*_RENAME`（差し替えのみ失敗）と `*_STRAND`（両方失敗）に
  分けて両方残した。故障点 14 → 17。
- ユーザー決定（2026-10-22）:
  - **各実装フェーズ後に `mise run build:nx93rank` を 1 回ずつ打つ**（計 3 回）。
    RANK.C を触ると `verify:nx93rank-binary` の sha256 照合が必ず赤くなり、ビルドは
    docker を引くので Claude は叩けない。これで全 turn が完全緑で閉じる。
  - **実機で `QCL RANK.C` を一度通す。** ファイルが 1.6 倍になるので、保険経路として
    残してある QuickC が生きているかを確かめる。失敗してもクロスビルドが正。
- 設計制約 2 件が計画に織り込まれたことを確認した。「取り込みは行数を数えない」は
  カウンタ不在という構造で充足（16 ビット溢れはホスト試験では原理的に捕まえられない
  ので、設計で消すしかない）。「移行は 1〜3 段を通常経路と共有」も充足したので、
  試験設計が刈った故障注入 8 組の復活は不要。

## 2026-10-22（続き・故障注入の見直し）

- **空振りの検査が 2 点見つかって塞いだ。** `*_STRAND` は対象ファイルが不在だと E15 に
  到達できない（`saved` が 0 のまま `!saved` 経路が先に FAILED を返す）。基線を「両表が
  不在のクリーン状態」にすると `R30_STRAND` と `WHO_STRAND` の 2 点が**黙って E14 を
  二度試すだけ**に縮退する。基線を「一度リセットさせて 4 枚を実在させてから注入」に
  固定し、縮退自体を見るケースを置いた。N1 と同じ種類の問題で、これで 2 件目。
- **`*_COMMIT` と `*_RENAME` は残留バイトで区別できない。** どちらも対象は旧内容のまま
  実在する。差は「退避名を経由したか」だけなので、画面出力の差分が E14 を E13 から分ける
  唯一の観測面になる。表明をそこに置いた。
- 移行側の `*_STRAND` は `TXT_STRAND` だけ残した。`TXT_RENAME`（E14）では復帰が成功して
  `NX93OLD.TXT` が消えるので、**退避先が `RANKOLD.TXT` ではなく `NX93OLD.TXT` である
  ことを観測できるのは `TXT_STRAND` だけ**。他 3 組は取り込み完了後で通常経路と区別が
  つかないので落とした。
- **ユーザー決定（決定 11）: 退避名を片付ける前に画面 1 行出す（W2）。** 終了コードは 0。
  E15 の後に残った唯一の回復コピーが、毎日更新だと 2 回目の跨ぎ（約 1 日後）に黙って
  消える経路があった。実害は小さい（消える中身は新しいファイル側にほぼ入っており、
  移行の `NX93OLD.TXT` はこの経路では消えない）が、「黙って消さない」を守る。
  メッセージは ASCII で書く（日本語は `GAME.BAT` の `ECHO` にしか置けない）。
