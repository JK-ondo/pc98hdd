## 2026-10-07 / 10-08

- ユーザーが ia16 クロスコンパイラ（Docker イメージ `ikkepop/ia16-tools`、
  ia16-elf-gcc 6.3.0）を見つけた。**決定1の前提「`.COM` は作れない」が崩れた**が、
  結論（入口は `GAME.BAT`）は残る 2 つの根拠で立つので設計は変えていない。
- 最初の試行は 2 点を取り違えていた。ひとつは `-mcmodel=small` を渡しておらず、
  「small」と称して既定の tiny を出していたこと（両成果物がバイト同一で露見）。
  もうひとつは拡張子 `RANK.C` が**大文字なので gcc が C++ として処理**し、
  `cc1plus: warning: '-std=c90' is valid for C/ObjC but not for C++` だけ出して
  `-std=c89` が無視されていたこと。C89 適合は検証されていなかった。
  小文字へ写して `-x c` を明示し、`-mcmodel` を明示して取り直した。
- 実測で分かったこと:
  - 素の `MSDOS` は未定義。ia16-elf-gcc が定義するのは `__MSDOS__` / `_DOS` /
    `__DOS__` / `__msdos86`。`RANK.C:66` の `#ifdef MSDOS` は効かず、`RANK_SEP` が
    `'/'` のまま警告もエラーも無しに通っていた。前処理で両経路を実測して確認。
  - C89 + `-pedantic -Wall -Wextra` で**警告ゼロ**。tiny 24206 / small 24240 バイト、
    どちらも 64KB に十分収まる。small は MZ ヘッダ（`4d5a`）を持つ。
  - 生成バイナリに `mov ah,2Ah`（DOS 日付取得）2 箇所、`mov ah,2Ch`（時刻取得）
    1 箇所、`int 21h` 17 箇所。**newlib は独自の時計を持たず汎用 MS-DOS コールに
    落ちている**ので、週次判定は PC-98 でも同じ経路で動く見込み。
  - RANK.C のメッセージ文字列がバイナリ中に確認でき、正しい原本が通っている。
- ユーザー決定（2026-10-07）: ビルドの正はクロスコンパイル、QuickC は保険。
  `dist/RANK.EXE` は git にコミットする。cmd-guard の allowlist は触らず、
  ビルドはユーザーが叩く。`#ifdef MSDOS` は広げる。
- 検査を先に書いて赤を確認してから直した。S8（`-D` なし → `RANK_DOS` 未定義かつ
  `RANK_SEP '/'`、`MSDOS` / `__MSDOS__` / `_DOS` の各々 → `RANK_DOS` 定義かつ
  `RANK_SEP '\\'`）と S9（綴りを含む前処理指令が 1 行だけ）。赤の内訳は
  `66:#ifdef MSDOS` と `910:#ifdef MSDOS` の 2 行を指していた。
- `#ifdef MSDOS` を単に広げるのではなく、判定を `RANK_DOS` 一箇所に集約した。
  綴りの一覧が 2 箇所にあると、片方だけ直して S8 が緑のまま穴が開く。
- `nx93rank/build.sh` を追加。イメージは**ダイジェストで固定**（`:latest` が動いて
  ビルド結果が黙って変わるのを防ぐ）。MZ ヘッダを確認してから `dist/` へ出し、
  由来の sha256 を `.built-from`（dist の外。dist の中身は全部 98 へ送られる）に記録する。
  `--check` は docker 不要で、未ビルドなら通し古いときだけ落ちる。
  `mise run verify` の `verify:nx93rank-binary` に接続。実際に RANK.C を変えて
  落ちること・戻して通ることを実測した（空振りの検査でないことの確認）。
- **`-DMSDOS` が不要になった**のが副産物。`RANK.C` 自身が ia16 の綴りを見るので、
  フラグを渡し忘れる経路が消えた。
- `mise run build:nx93rank` の成果物が、`-DMSDOS` を明示した調査時のバイナリと
  **バイト単位で完全一致**した。綴りの拡張が実際のクロスビルドで効いている直接証拠。
  24240 バイト、sha256 `5310b875fb48...`。
- `README.md:146` の誤記を訂正した。「カレントディレクトリの NX93.SCR を読む」と
  書いてあったが、実装は `rank_dir_from_argv0` で `argv[0]` の居場所を使う。
- 段取り: spec-writer と architect を飛ばした。plan に「`MSDOS` 定義の有無で
  切り替える」が既にあり、綴りを増やして 1 箇所に寄せるだけで契約が変わらないため。
  検査は test-designer を通さず test-design.md の体裁に合わせて自分で書いた。
- 未検証のまま残るもの（クロスコンパイルでは縮まない）: newlib の `fopen` が
