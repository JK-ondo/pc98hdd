# NyaHaX'93 週次ランキングリセット

## 目的

NX93.SCR は上位 10 件しか持たないため、強い一人が上位を占め続けると他の人の記録が
入らなくなる。週に一度、各人の最高記録 1 件だけを残してデフォルトランキングへ差し戻し、
席を空ける。消す前の表は必ず全件バックアップする。

## 決定事項（2026-09-28 ユーザー承認）

1. 入口は `GAME.BAT`、更新プログラムは `RANK.EXE`。
   - MS-DOS のコマンド解決順は COM → EXE → BAT。`GAME.COM`/`GAME.EXE` を置くと
     `GAME.BAT` が実行されなくなるため、更新プログラムは別名にする。
   - BAT 方式なら更新プログラムは終了済みで、ゲームの空きメモリを削らない。
   - 当初の根拠「`.COM` は作れない」（QuickC 2.00 同梱の LINK.EXE に `/TINY` が無く、
     A:\DOS にも pc98/ のどの DOS にも EXE2BIN が無く、アセンブラも無い）は
     2026-10-07 に崩れた。ia16-elf-gcc は `-mcmodel=tiny` で `.COM` を出せる。
     結論は上の 2 点だけで立つので変えていない。
2. デフォルトランキングは RANK.C に定数として埋め込む（実機に置くファイルを増やさない）。
   出典は `~/test/nx93_110/NX93.SCR`（配布アーカイブ nx93_110.lzh の原本）。
3. 初回実行時（NX93.TXT が無い）は「最終更新日時なし＝一週間以上前」とみなして
   その場でリセットする。バックアップが先なので現在の表は失われない。

## 対象ファイル（すべて A:\GAME\NX93\ 上）

| ファイル | 役割 |
| --- | --- |
| `NX93.SCR` | ゲーム本体が読み書きするランキング。10 行・CRLF |
| `NX93.TXT` | 本システムの状態＋バックアップ台帳（JSON） |
| `RANK.EXE` | 更新プログラム。RANK.C を 98 上で QCL でビルドする |
| `GAME.BAT` | 入口。RANK → NX93 の順に起動する |

## NX93.SCR の形式（実データで確認済み）

```
327400 30 01 OMZN     26/09/15 A<CR><LF>
 ^score ^lv ^miss ^name(8) ^YY/MM/DD ^mode(A=AUTO / M=MANUAL)
```

- スコアは桁数が一定しない。配布原本は `080000` と 0 詰め、ゲームが書いた行は `98840`
  と 5 桁。したがって**先頭から固定長で読んではいけない**。
- 末尾側は固定長。行末から `mode`(1) `SP` `date`(8) `SP` `name`(8) と数えれば、
  名前に空白が含まれていても切り出せる。
- 行は**バイト列のまま保持して書き戻す**。ゲーム側の読み取りを壊さないための原則。
- 名前に `%` が入りうる（デフォルトの `Bio_100%`）。`printf(line)` は禁止、`fputs` を使う。

## 更新の規則

1. `NX93.TXT` の `lastUpdate` を読む。
   - 無い（ファイルごと無い）→ リセットする。
   - 読めるが 7 日未満 → **何もせず** 終了コード 0。ゲームが起動する。
   - 壊れている（`lastUpdate` を取り出せない）→ **何も書き換えず** 終了コード 1。
     台帳を壊さないほうを優先する。
   - **未来**（`lastUpdate` が現在より後）→ **何も書き換えず** 終了コード 1。
     RTC の電池切れで時計が巻き戻った状態。表を動かさずに GAME.BAT の PAUSE で
     知らせ、`DATE` で直してもらう。黙って見送るとリセットが永久に来なくなる。
   - `NX93.SCR` に読めない行がある、または 11 行以上ある → **何も書き換えず**
     終了コード 1。読めなかった行を黙って捨てない。
2. リセットする場合:
   1. 先にバックアップ。`NX93.TXT` を新しい内容で書き直す（後述）。ここまで成功して
      初めて `NX93.SCR` に触る。
   2. 現在の 10 件を名前で重複除去する。名前は前後の空白を落とし、**大文字小文字を
      区別せず**比較し、同名は最高スコアの 1 件だけ残す。
   3. 残った件をデフォルトランキング 10 件と併合し、スコア降順で上位 10 件を採る。
      同点は「現在の表の行」→「デフォルトの行」、同じ出自なら元の並び順（安定ソート）。
      デフォルト側は重複除去しない（`Bio_100%` 10 件は席を埋める役）。
   4. `NX93.SCR` へ書く。

## NX93.TXT の形式

```json
{
  "lastUpdate": "2026-09-28T21:40:00",
  "backups": [
    {
      "backupAt": "2026-09-28T21:40:00",
      "ranking": [
        "327400 30 01 OMZN     26/09/15 A"
      ]
    }
  ]
}
```

- `backups` は新しい順。毎回の追加は先頭への挿入。
- 追加は**全体を読み込まずに**行う。`"backups"` の `[` まで読み、新項目を書き、
  古い中身は残りをそのままバイトコピーする。台帳は週 400 バイト程度で増え続けるので、
  メモリに載せない。

## 実装方針

- 言語は C89。ビルドの正は Mac 上のクロスコンパイル（`nx93rank/build.sh` →
  ia16-elf-gcc 6.3.0、`-mcmodel=small` で MZ 実行形式）。98 上の QuickC 2.00
  （`QCL RANK.C`）は保険として残し、RANK.C はどちらでも通る状態を保つ。
  どちらも small モデル既定でよい。2026-10-07 ユーザー承認。
- ファイルはすべてバイナリモードで開き、改行は明示的に `\r\n` を書く。
- **RANK.C 内のメッセージは ASCII に限る。** Shift-JIS の 2 バイト目に 0x5C を含む字
  （ソ 表 十 能 等）が QuickC でエスケープとして解釈される事故を避けるため。
  日本語を出したい箇所は GAME.BAT の ECHO に置く（バッチはエスケープ解釈が無い）。
- 書き換えは一時ファイルへ全部書いてから差し替える。途中で失敗したら既存に触らない。
- 差し替えは復帰可能な 3 段。旧ファイルを `RANKOLD.*` へ退避 → 一時ファイルを本名へ →
  退避を削除。2 段目が失敗したら退避から戻す。DOS には置換する rename が無く、
  `remove` してから `rename` が失敗すると旧ファイルが消えたまま残るため。台帳は
  このシステムが存在する理由そのものなので、それを失う経路を残せない。
  戻す rename まで失敗した場合だけは「無変更」と言わず、`RANKOLD.*` から手で戻す
  手順を表示する。
- 読み書きする場所は**カレントではなく `argv[0]` から取った自分の居場所**。ユーザーは
  DOSSHELL から起動するため、カレントが `A:\GAME\NX93` 以外になる経路が実在する。
  ゲーム本体も NX93.EXE のあるディレクトリから NX93.SCR を読むので、挙動が揃う。
- DOS 向けビルドかどうかの判定は `RANK_DOS` 一箇所に集約する。共通の綴りが無く、
  QuickC は `MSDOS`、ia16-elf-gcc は `__MSDOS__` と `_DOS` を定義する（素の `MSDOS`
  は定義しない）。外しても警告なしで通り、パスの区切りが `/` のまま `A:` が
  ドライブ接頭辞として扱われなくなるだけなので、綴りの一覧は 1 箇所しか置かない。
- Mac 側では clang で同じ RANK.C をビルドして回帰テストを回す。時刻は
  テストビルドでのみ差し替え可能にする（DOS ビルドには入らない）。

## リポジトリ上の置き場所

```
nx93rank/
├── dist/           98 へ送るものだけ（98hdd send nx93rank/dist /GAME/NX93）
│   ├── GAME.BAT
│   ├── RANK.C      QuickC へ戻すための原本。送るが 98 上では普段使わない
│   └── RANK.EXE    build.sh の成果物。コミットする
├── build.sh        RANK.C → dist/RANK.EXE（Docker 経由の ia16-elf-gcc）
├── .built-from     dist/RANK.EXE が由来する RANK.C の sha256
├── tests/          Mac 側の回帰テスト
└── README.md       ビルド手順と運用
```

`dist/RANK.EXE` はコミットする。`dist/` が「98 へ送る物一式」である意味を保ち、
送信が Docker を必要としなくなる。古い実行形式が混じる危険は
`mise run verify`（`verify:nx93rank-binary`）が sha256 で落として塞ぐ。
2026-10-07 ユーザー承認。

`hdd/` は実機のミラー（pull の出力）なので、ここには書かない。
