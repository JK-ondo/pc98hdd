# 仕様: 98hdd の複数カード対応

対象は `98hdd.sh`（現行 499 行）と `SPEC.md`・`README.md`・`README.ja.md`。
実装より先に書いた契約で、観測可能な振る舞いだけを述べる。判断の由来は `plan.md`。
計画と食い違ったら計画が正で、この仕様を直す。

実測で裏付けた前提は §8 にまとめてある。

## 1. 目的

複数の SD カード（HDD イメージ）でデータを保管できるようにする。98 が同時に認識するのは
1 枚のままで、カードを挿し替えて使う。

**この機能の本体は利便性ではなく安全性である。** 現行は実効の書き込み先が
`~/.mtoolsrc` にあり、`~/.98hddrc` の `HDD_IMAGE` は存在チェックにしか使われない。
1 枚のうちは一致が崩れないので欠陥として現れないが、2 枚目を挿した日に
**「存在チェックは B で通り、mtools は A に書く」**という形で顔を出す。
複数対応とは、この二重管理を潰すことである。

## 2. 非目標

- 同時に 2 枚を扱うことはしない。98 側の制約ではなく、この道具が 1 枚ずつ挿す運用を
  前提にする。2 枚マウントされていたら曖昧として**止める**（§5 E3）。
- カードの作成・フォーマット・パーティション操作はしない。既にあるイメージを扱うだけ。
- `fd`（FDI 展開）と `pc98/` は触らない。カードと無関係。
- 8.3 名変換・文字コード変換・`TEXT_EXTS` の規則は変えない。
- `hdd/` の中身を自動で移動しない。既存利用者に移行作業を課さない（§3.2）。
- イメージの内容による同定（ハッシュなど）はしない。200 MB を毎回読むことになる。

## 3. 公開面

### 3.1 カードの定義

カードは `~/.98hdd/cards/<名前>.conf` に 1 枚 1 ファイルで定義する。シェルとして
source されるので、既存の `~/.98hddrc` と同じ作法で書ける。

```sh
IMAGE="/Volumes/x/HD10_512 200MB.hda"
OFFSET=360448
SERIAL="0C01-0A1F"          # 同定の鍵（§3.3）
PULL_DIR="${HOME}/9801/hdd/main"
# SEND_DIR=...              # 省略時はグローバルの値
```

| 変数 | 必須 | 意味 |
| --- | --- | --- |
| `IMAGE` | **必須** | イメージファイルのパス |
| `OFFSET` | **必須** | FAT パーティション先頭へのバイトオフセット |
| `SERIAL` | **必須** | FAT のボリュームシリアル番号。`XXXX-XXXX` 形式 |
| `PULL_DIR` | 任意 | 省略時は `<BASE_DIR>/hdd/<名前>` |
| `SEND_DIR` | 任意 | 省略時はグローバルの `SEND_DIR` |

`<名前>` はファイル名から取る。**1 文字目は `[A-Za-z0-9]`、2 文字目以降は
`[A-Za-z0-9_-]`。** それ以外を含むファイルは**読み飛ばさずエラーにする**（E7）。
黙って無視すると、設定したつもりのカードが存在しないことになる。

**1 文字目からハイフンを除くのは、名前が選択肢に化けるのを防ぐため。** `-x.conf` を
許すと `98hdd -c -x pull` のような呼び方が生まれ、引数解釈が名前とオプションを
区別できなくなる。カード名は人が打つ識別子なので、この 1 文字分の制限は払っていい。

### 3.1.1 カード情報の受け渡し（bash 3.2 の制約）

macOS の `bash` は **3.2.57** で、**連想配列が使えない**（`98hdd.sh:184` が既に
この前提を書いている）。カードの集合を持ち回る形は**行指向**にする。

```
load_cards    → 1 枚 1 行で name|image|offset|serial|pull_dir を標準出力へ。
                不備があれば標準エラーへ述べて終了 1（E7・E8・E5）
select_card   → 選んだ 1 枚の同じ形式の行を標準出力へ。
                選べなければ標準エラーへ述べて終了 1（E1〜E4・E6・E9）
```

区切りは `|`。カード名とシリアルには現れない文字で、`IMAGE` と `PULL_DIR` のパスに
現れる見込みも低い（現れたら E7 と同じ扱いで止める）。並行する添字配列を使う形は
採らない — 枚数と添字の対応を手で保つ必要があり、1 箇所ずれると別のカードの
`IMAGE` に別のカードの `SERIAL` を当てる経路ができる。

### 3.2 暗黙の `default` カード（後方互換）

`~/.98hdd/cards/` が存在しないか、`.conf` が 1 つも無い場合、`~/.98hddrc` の
`HDD_IMAGE`・`HDD_OFFSET`・`PULL_DIR` から**暗黙のカード `default` を組み立てる**。

- `PULL_DIR` は `~/.98hddrc` の値（既定 `<BASE_DIR>/hdd`）をそのまま使う。
  **`hdd/default/` にはしない。** 既存利用者のミラーは動かない。
- `SERIAL` は定義されていないので、**同定の照合を行わない**（§3.3 の例外）。
  現行と同じ振る舞いになる。
- この経路に入ったことは `pull`・`send`・`ls` の冒頭で 1 行告げる。黙って旧経路に
  落ちると、利用者は新機能が効いていると誤解する。

つまり**今までどおり使っている人は、何もしなくても今までどおり動く**。

**ただし 1 点だけ変わる。** 現行の `HDD_OFFSET` は**使われていない**（実効値は
`~/.mtoolsrc` 側）。この機能で `~/.mtoolsrc` を読まなくなるので、`HDD_OFFSET` が
未使用から**実効値**に変わる。2 つのファイルで値が食い違っていた利用者は、今までは
ズレたまま動いていたが、これからは `~/.98hddrc` の値が使われる。

食い違っていれば FAT の先頭を指さないので、**E9 で止まる**（黙って別の場所を読み書き
しない）。移行の案内として、E9 の文面は「オフセットが違っている可能性が高い」ことを
述べ、README は `~/.mtoolsrc` の値を `~/.98hddrc` へ写すよう案内する。

### 3.3 同定

カードの同定は **FAT のボリュームシリアル番号**で行う。イメージのブートセクタ
オフセット `0x27` から 4 バイト、リトルエンディアン。`<OFFSET>+39` バイト目から読む。

```
<OFFSET>+0x26  拡張ブート署名。0x29 でなければシリアル欄は無効（E9）
<OFFSET>+0x27  シリアル 4 バイト（リトルエンディアン）

実測例: 29 | 1f 0a 01 0c  →  "0C01-0A1F"
             └ 4 バイトを逆順に並べ、大文字 16 進 8 桁、中央にハイフン
```

mtools を起動せずに読める。FAT が壊れていても読め、イメージ全体を走査しない。

**読む前に拡張ブート署名を確かめる。** `0x26` が `0x29` でなければ、その位置は
シリアル欄ではない（FAT の仕様上、署名があるときだけシリアルとラベルが置かれる）。
確かめずに 4 バイト読むと、**無関係なバイトをシリアルとして扱い、たまたま一致すれば
別のイメージへ書く**。fail closed にするため、署名が無ければ E9 で止める。

**照合の規則。** カードを選んだあと、最初の mtools 呼び出しより前に照合する。

| 状況 | 振る舞い |
| --- | --- |
| `IMAGE` が存在しない | E1 で終了 1 |
| 拡張ブート署名が `0x29` でない | **E9 で終了 1** |
| 読めたシリアルが `SERIAL` と一致 | 進む |
| 一致しない | **E2 で終了 1。何も読み書きしない** |
| `SERIAL` 未定義（暗黙 `default` のみ） | 照合しない。進む |

**シリアルは同定であって認証ではない。** カードを丸ごと複製すれば両方が同じシリアルを
持つ。複製したうえで別々に使い分けたいなら、同じシリアルの 2 枚は区別できない。
その場合は `-c` で明示指定するか、片方を再フォーマットすること。仕様としてこれを許す。

### 3.4 カードの選び方

```
98hdd [-c <名前>] <コマンド> ...
```

| 状況 | 選ばれるもの |
| --- | --- |
| `-c <名前>` あり | その名前のカード。無ければ E6 |
| `-c` なし・カード定義が 1 枚 | その 1 枚 |
| `-c` なし・複数あり | **2 段で絞る**（§3.5） |
| カード定義が 0 枚 | 暗黙の `default`（§3.2） |

**`-c` はサブコマンドの前に置く。** 後ろに置いた `-c` は**無視する**
（`98hdd pull -c a` は `98hdd pull` と同じ）。拒否しない理由は、`send` と `ls` が
位置引数でパスを受け取るので、後置の `-c` を一般に検出しようとすると
「パスとして `-c` を渡したい」場合と区別できなくなること。現行の
`cmd_send`（`$1` と `$2` のみ参照）と `cmd_ls`（`$1` のみ参照）は、後ろに付いた
余分な引数を既に落としている。

**代わりに、選んだカードを必ず名前で告げる**（下記）。これが無いと、無視された `-c` は
観測できない。

### 3.4.1 選んだカードは必ず告げる

`pull`・`send`・`ls` は、最初の読み書きより前に**選んだカード名を 1 行出す**。
`-c` による指定か自動判定かも述べる。

```
[INFO]  カード: main（自動判定）
[INFO]  カード: games（-c 指定）
[INFO]  カード: default（カード定義が無いので ~/.98hddrc から）
```

**これが後置 `-c` を無視することの安全弁である。** `98hdd pull -c a` と打って
`カード: b（自動判定）` が出れば、利用者はその場で気づける。黙って別のカードを
扱うことにはならない。

### 3.5 自動判定

`-c` 無しで複数定義されている場合、**2 段で絞る**。

**段 1（候補を集める）。** 各カードの `IMAGE` が存在するかを見る（`[[ -f ]]`）。
存在するものが候補。

**段 2（シリアルで絞る）。** 候補それぞれについて、その `(IMAGE, OFFSET)` から
シリアルを読み（§3.3）、宣言された `SERIAL` と一致するものだけを残す。

| 段 2 の残り | 振る舞い |
| --- | --- |
| ちょうど 1 枚 | それを選び、選んだ名前を 1 行告げる |
| 0 枚 | E4 で終了 1。候補が 1 つ以上あったなら、**そこで実際に読めたシリアルを出す** |
| 2 枚以上 | **E3 で終了 1。** 本当に別々のイメージが 2 つ以上マウントされている |

**段 2 が無いと、最も普通の構成で使えなくなる。** BlueSCSI のカードを同じ手順で
2 枚作れば、ボリュームラベルもイメージのファイル名も同じになる。両方の `.conf` が
`/Volumes/x/HD10_512 200MB.hda` を指すことになり、段 1 だけでは「候補 2 つ＝曖昧」と
判定される。しかし 1 枚ずつ挿す運用では**実際に存在するイメージは 1 つ**なので、
シリアルを読めば必ず 1 つに絞れる。実測したイメージのボリュームラベルは `NO NAME` で
空であり、**ラベルでは絞れない**ことも確かめてある。

したがって E3 は「同じ場所を指す定義が複数ある」ではなく、**「別々のイメージが
2 つ以上同時にマウントされていて、それぞれ自分のプロファイルと一致している」**という
意味になる。これは本当に曖昧なので選ばない。

**曖昧なときに「最初の 1 枚」を選ばない。** 選べば、利用者が意図していないカードへ
書く道が開く。この機能の目的に反する。

`-c` で明示指定した場合は段 1・段 2 を行わず、名指されたカードについて §3.3 の照合だけを
行う。他のカードが何枚マウントされていても関係ない。利用者が名指したものが正である。

### 3.6 `pull` の展開先

選ばれたカードの `PULL_DIR` へ展開する。既定は `<BASE_DIR>/hdd/<名前>`（暗黙の
`default` だけは `<BASE_DIR>/hdd`）。他の振る舞い（追記型であること・変更されるファイルを
`.bak_<時刻>` へ退避すること・件数の報告）は現行のまま変えない。

**異なるカードの `PULL_DIR` が同じ場所を指していたら、読み書きの前に E5 で止める。**
設定の誤りでミラーが混ざるのを防ぐ。比較は実パス（シンボリックリンク解決後）で行う。

### 3.7 新しいコマンド

```
98hdd card list              定義されているカードを一覧する
98hdd card show [<名前>]     1 枚の設定と、今マウントされているかを出す
```

どちらも読み取りのみ。`card list` は名前・`IMAGE` の有無・`PULL_DIR` を出す。
シリアルの照合結果も出す（一致・不一致・未定義）。

**カードを作るコマンドは設けない。** `.conf` は 5 行のシェルで、手で書くほうが速く、
生成すると「何が書かれたか」を読まない利用者が増える。`98hdd card show` が
**今挿さっているイメージの実測シリアルを出す**ので、それを貼れば定義が完成する。

### 3.8 mtools の呼び出し

**すべての mtools 呼び出しを `-i "<IMAGE>@@<OFFSET>"` ＋ `::` 形式に統一する。**
ドライブ文字（`p:`）と `~/.mtoolsrc` は読まない。

- 既存の `run_mtools() { MTOOLS_SKIP_CHECK=1 "$@"; }` は維持する。**この環境変数は
  必須である**（§8）。
- `HDD_DRIVE` 設定は意味を失う。`~/.98hddrc` にあっても無視し、`card list` でも出さない。
  **撤去はしない** — 公開済みの設定ファイルを読み込み時にエラーにしない。

## 4. 不変条件

- **I1: 照合前に書かない。** シリアル照合が終わるまで、いかなる mtools 呼び出しも
  行わない。読み取りも含む（E2 の時点で「どのイメージを読んだか」が不確かなため）。
- **I2: 失敗したら何も変えない。** §5 のどのエラーでも、イメージと `PULL_DIR` の
  どちらも変更されていない。
- **I3: 1 回の起動が触るイメージは 1 つだけ。** 選ばれたカードの `IMAGE` 以外を
  開かない。自動判定の存在チェックは `[[ -f ]]` とシリアル読み取りに留め、
  選ばれなかったイメージへは mtools を向けない。
- **I4: カードを定義していない利用者の振る舞いは、`HDD_OFFSET` が正しい限り変わらない。**
  暗黙の `default` を通る経路は、展開先・メッセージの要点・終了コードのいずれも現行と
  同じ。**唯一の例外は `HDD_OFFSET`** で、未使用から実効値に変わる（§3.2）。
  食い違っていれば E9 で止まり、黙って別の場所を読み書きすることはない。
- **I5: 同じ引数の再実行は同じ結果になる。** 自動判定はマウント状態だけに依存し、
  実行順に依存しない。

## 5. エラー分類

いずれも終了コード **1**。語彙は {0, 1} のまま増やさない（現行の方針）。

| | 条件 | 文面が述べること |
| --- | --- | --- |
| **E1** | `IMAGE` が存在しない | カード名と、探したパス |
| **E2** | シリアルが一致しない | カード名・期待したシリアル・実際に読めたシリアル・**どのカードなら一致するか**（定義済みの中に該当があれば名指す） |
| **E3** | 自動判定の段 2 で 2 枚以上残った | 残った名前を全部・`-c` で選ぶこと |
| **E4** | 自動判定の段 2 で 0 枚になった | 定義済みの名前を全部・カードを挿すか `-c` を使うこと。**段 1 の候補が 1 つ以上あったなら、そこで読めたシリアルも出す**（「挿さってはいるが、どの定義とも一致しない」と「何も挿さっていない」は別の事態で、利用者の次の一手が違う） |
| **E5** | 複数のカードの `PULL_DIR` が同じ | 衝突している 2 つ以上の名前と、その実パス |
| **E6** | `-c` の名前が定義されていない | 与えられた名前・定義済みの名前を全部 |
| **E7** | `.conf` のファイル名が許されない文字を含む | そのファイル名と、許される文字 |
| **E8** | `.conf` に `IMAGE`・`OFFSET`・`SERIAL` のいずれかが無い | カード名と、欠けている変数名 |
| **E9** | 拡張ブート署名が `0x29` でない | カード名・`IMAGE`・`OFFSET`・読めた署名の値。**オフセットが違っている可能性が高い**ことを述べる（FAT の先頭を指していないと、この位置は別のデータになる） |

**E2 が「どのカードなら一致するか」を述べるのは必須である。** 利用者が知りたいのは
「違う」ことではなく「では何が挿さっているのか」であり、それはこの道具が知っている。

## 6. 資源・並行性

- 同定のためにイメージを開くのは 4 バイトの読み取りのみ（`od -j <OFFSET>+39 -N 4`）。
  イメージ全体を読まない。
- 自動判定は定義数ぶんの `[[ -f ]]` とシリアル読み取りで、定義が 10 枚でも体感差は無い。
- 並行実行は想定しない。2 つの `98hdd` が同じイメージへ同時に書けば壊れるが、これは
  現行と同じで、この機能では変えない。

## 7. 受け入れ基準

実装がこれらを満たすことを試験で確かめる。詳細な入力とオラクルは試験設計で詰める。

### A. 後方互換（最優先）

- A1: `~/.98hdd/cards/` が無く `~/.98hddrc` だけがある状態で、`ls`・`pull`・`send` が
  現行と同じ展開先・同じ終了コードで動く。
- A2: その経路に入ったことを 1 行告げる。
- A3: `~/.98hddrc` に `HDD_DRIVE` が残っていてもエラーにならない。
- A4: **`HDD_OFFSET` が実効値になる。** 誤った値なら E9 で止まり、黙って別の場所を
  読み書きしない。これが現行と変わる唯一の点であり、README に移行案内を書く。

### B. 選択

- B1: 定義 1 枚・`-c` 無し → それが選ばれる。
- B2: 定義 3 枚のうち `IMAGE` が存在するのが 1 つ → それが選ばれ、名前が出る。
- B3: **定義 3 枚が全部同じ `IMAGE` パスを指し、そのパスが存在する**（BlueSCSI の
  カードを同じ手順で作った場合の普通の構成）→ 段 2 のシリアルで**ちょうど 1 枚に絞られ、
  それが選ばれる**。E3 にしない。
- B4: 別々のパスのイメージが 2 つ存在し、どちらも自分の `SERIAL` と一致 → **E3 で
  終了 1。何も読み書きしない。**
- B5: 定義 3 枚のうち 0 つ存在 → E4 で終了 1。
- B6: `IMAGE` は存在するが、どの定義の `SERIAL` とも一致しない → E4 で終了 1。
  **文面に、実際に読めたシリアルが出る**（定義を書き足すのに必要な値がそのまま手に入る）。
- B7: `-c` 指定は段 1・段 2 を行わず、他が何枚マウントされていても指定どおりに進む。
- B8: `-c` に未定義の名前 → E6 で終了 1。

### C. 同定

- C1: シリアル一致 → 進む。
- C2: シリアル不一致 → **E2 で終了 1。イメージも `PULL_DIR` も変わらない。**
- C3: E2 の文面に、期待値・実測値・一致するカード名が出る。
- C4: ブートセクタから読んだシリアルが `mdir` の言う値と一致する（§8 で実測済み）。
- C5: `SERIAL` 未定義の暗黙 `default` では照合しない。
- C6: 拡張ブート署名が `0x29` でないイメージ → **E9 で終了 1。シリアルを読まない。**
- C7: `OFFSET` を意図的にずらした定義 → E9 で止まる（署名が合わないため）。
  **誤ったオフセットが黙って通らない**ことの確認。

### D. 隔離

- D1: 2 枚定義し、片方へ `send` したあと、もう片方のイメージが**バイト不変**。
- D2: 2 枚それぞれを `pull` したあと、2 つの `PULL_DIR` が互いに干渉しない。
- D3: `PULL_DIR` が衝突する定義 → E5 で終了 1。シンボリックリンク経由の衝突も捕まえる。

### E. 設定の不備

- E1〜E9 の各条件が、それぞれ**互いに異なる文面**で出る。
- `.conf` の必須変数が欠けていたら E8。黙って既定値に落とさない。

### F. 実機（ユーザー作業）

- F1: 2 枚のカードで、挿し替えてそれぞれ `pull` できる。
- F2: **わざと間違える** — カード A を挿して `-c <B>` を指定し、E2 が出て何も起きないこと。
      これがこの機能の本体なので、落ちるところを見ないまま終えない。

## 8. 実測で裏付けた前提（2026-11-16）

控えのイメージ（原本と sha256 一致、209,780,736 B）で測った。

| 前提 | 結果 |
| --- | --- |
| `-i "<img>@@<offset>"` で読める | `p:` 経由と**全 1,860 パス一致・空き容量一致** |
| ジオメトリ（`cylinders`/`heads`/`sectors`）が要る | **要らない** |
| `MTOOLS_SKIP_CHECK=1` が要る | **要る。** 無いと `Bad media types fe/f8` で落ちる |
| `-i` で書ける | `mcopy -o` で 15 バイトが往復してバイト一致 |
| `-i` で `mmd -D s` できる | 成功 |
| FAT が壊れない | 増えたパスは**ちょうど 3 件**、消費は 4 KB × **3 クラスタ**。他に変化なし |
| ブートセクタからシリアルを読める | `od -j <OFFSET>+39 -N 4` が `0C01-0A1F`。`mdir` の出力と一致 |

**`MTOOLS_SKIP_CHECK=1` が必須であることは、この仕様の土台である。** 最初の試行で
これを落として失敗し、「ジオメトリが必要」という誤った結論に達しかけた。
