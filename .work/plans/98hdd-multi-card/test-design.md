# テスト設計: 98hdd の複数カード対応

原典は `spec.md`。ケースは仕様の意図から起こし、実装の振る舞いからは逆算しない。
`98hdd.sh` には**現在ひとつも試験が無い**ので、ハーネスから作る。

## 0. 検算したこと（オラクルの出所）

実装を読まずに、道具の実際の振る舞いを測って出した。

| 対象 | 方法 | 結果 |
| --- | --- | --- |
| `-i "<img>@@<off>"` が `p:` と同じものを読む | 実機イメージの控えで `mdir -s -b` を両方 | **1,860 パス全一致・空き容量一致** |
| ジオメトリの要否 | 同上 | **不要**（`cylinders`/`heads`/`sectors` を与えずに通る） |
| `MTOOLS_SKIP_CHECK=1` の要否 | 付けずに実行 | **必須**。`Bad media types fe/f8` で落ちる |
| `-i` での書き込み | `mcopy -o` → `mcopy -n` で往復 | 15 バイトがバイト一致 |
| `-i` での `mmd -D s` | 実行 | 成功。増えたパスは**ちょうど 3 件**、消費は 4 KB × **3 クラスタ** |
| FAT16 のシリアル位置 | 実機イメージを `od` | `0x26`=`0x29`、`0x27` の 4 バイトが `1f 0a 01 0c` → `0C01-0A1F`。`mdir` の出力と一致 |
| 実機イメージのラベル | `od -j <off>+43 -N 11 -c` | **`NO NAME`（空）**。ラベルでは同定できない |
| **FAT32 のシリアル位置** | `mformat -F` で作って `od` | 署名は `0x42`、シリアルは `0x43`。**`0x26` は `0x00`** |
| 試験用イメージを作れるか | `mformat -i <img>@@<off> -T 32768 -N <serial> ::` | **作れる。** FAT16・署名 `0x29`・指定したシリアルが `0x27` に入る |
| その実消費 | `du -k` | **496 KB**（`-T 32768`）。`-T 16384` だと FAT12 になり、かえって 9.5 MB 食う |
| `98hdd.sh` を source できるか | 末尾を読んだ | **できない。** 499 行目の `main "$@"` が無条件に走る |
| 設定パスの由来 | `grep HOME` | `BASE_DIR` と `CONFIG_FILE` が `${HOME}` からのみ派生。**`HOME` の差し替えで隔離できる** |

**副産物: FAT32 は E9 で自動的に弾かれる。** FAT32 の `0x26` は `FATSz32` の上位ワードで、
通常 `0x00` である（実測でも `0x00`）。署名を確かめる規則が、意図せず
「PC-98 DOS が扱えない形式を受け付けない」という正しい振る舞いも与えている。

## 1. 実装側に要る変更（試験可能性）

試験を書くために実装が満たすべきこと。**仕様の振る舞いは変わらない。**

- **N1: `main "$@"` を `if [[ "${BASH_SOURCE[0]}" == "${0}" ]]; then main "$@"; fi` にする。**
  これが無いと `source` が全部実行してしまい、単体試験が 1 本も書けない。
  実行したときの振る舞いは変わらない。
- **N2: シリアル読み取り・カード選択・名前検証を、それぞれ独立した関数にする。**
  `cmd_pull` の中に直書きすると単体で呼べず、統合試験だけで決定表 9 行を張ることになる。
- **N3: mtools の呼び出しをすべて 1 箇所（`run_mtools`）に通し続ける。** 試験が
  偽の mtools を `PATH` 先頭に置いて呼び出しを観測するため（§5.1）。直接 `mdir` などを
  呼ぶ経路が増えると、その経路だけ観測から漏れる。
- **N4: 素の `mktemp` を `mktemp "${TMPDIR:-/tmp}/98hdd.XXXXXXXX"` にする**（5 箇所：
  87・155・270・284・373 行）。**macOS の `mktemp` は引数なしだと `TMPDIR` を無視して
  `/var/folders/.../T/` を使う**ので、`TMPDIR` を絞った環境では
  `Operation not permitted` で落ちる。`nx93rank/tests/run.sh` は既に明示的な雛形を
  使っており（`mktemp -d "${TMPDIR:-/tmp}/nx93rank.XXXXXXXX"`）、**98hdd.sh だけが
  プロジェクトの作法から外れている**。通常の環境での振る舞いは変わらない。

## 2. ハーネス

### 2.1 隔離

すべての試験は `HOME` を差し替えた砂場で走らせる。

```sh
scratch=$(mktemp -d "${TMPDIR:-/tmp}/98hdd.XXXXXXXX")
trap 'rm -rf "$scratch"' EXIT HUP INT TERM
HOME="$scratch" bash 98hdd.sh <args>
```

これで `~/.98hddrc`・`~/.98hdd/cards/`・`<BASE_DIR>/hdd`・`<BASE_DIR>/send` が
すべて砂場に入る。**利用者の実環境と実イメージに一切触れない。**

### 2.2 試験用イメージ

```sh
make_image() {           # make_image <path> <serial8hex>
    local img="$1" serial="$2" off=360448
    dd if=/dev/zero of="$img" bs=1 count=0 \
       seek=$(( off + 32768*512 + 1048576 )) 2>/dev/null
    MTOOLS_SKIP_CHECK=1 mformat -i "${img}@@${off}" -T 32768 -N "$serial" ::
}
```

FAT16・署名 `0x29`・指定シリアル・実消費 496 KB。オフセット 360448 は実機と同じにする
（オフセットが 0 でない構成を試験の既定にしておかないと、`@@` を落とす欠陥が通る）。

**異常系のイメージ。**

| 名前 | 作り方 | 用途 |
| --- | --- | --- |
| `bad_sig` | `mformat` を**しない**（ゼロのまま） | 署名が `0x00` → E9 |
| `fat32` | `mformat -F` を足す | 署名が `0x26` に無い → E9。実在しうる誤りの再現 |
| `truncated` | オフセット + 16 バイトだけのファイル | 読む前にファイル末尾 → E9（読めないことを 0x29 でないとして扱う） |

### 2.3 mtools の観測（偽コマンド）

`I1`（照合前に mtools を呼ばない）と `I3`（触るイメージは 1 つ）は、**呼び出しが
起きなかったこと**を見る必要がある。結果の状態を見るだけでは張れない。

```sh
# $scratch/bin を PATH 先頭に置く。各偽コマンドは引数を $MTOOLS_LOG へ 1 行追記し、
# MTOOLS_PASSTHROUGH=1 なら本物へ exec、さもなくば終了 0 で何もしない。
```

- 対象は `mdir` `mcopy` `mmd` `mformat`。
- ログの行数・`-i` に渡された綴りを表明できる。
- **通過させる版（本物を呼ぶ）と、遮る版（呼ばない）の 2 形**を使い分ける。
  遮る版は「ここまで来ていないはず」を強く見るのに使う。

## 2.4 否定の表明には必ず肯定の相方を付ける

実装中に**同じ型の欠陥を 3 回作った**ので、方針として書く。

| 出た形 | なぜ通ってしまったか |
| --- | --- |
| `assert_ne "exit" 0` | 関数が未実装なら `127` で、これも「非ゼロ」を満たす |
| `assert_contains "a"` | 1 文字の針は `bash: line 3: load_cards: command not found` に当たる |
| 「終了 1・行き先が無い・mtools が呼ばれていない」 | `-c` が未実装なら「不明なコマンド」で落ち、3 つとも満たす |

**規則。**

- **終了コードは「ちょうど 1」を要求する**（仕様が語彙を {0,1} に限っている）。
  「非ゼロ」では未実装の `127` と区別できない。
- **針は識別力のある綴りにする。** カード名は `alpha`・`bravo`・`charlie` を使う。
- **不変性・不在・無呼び出しの表明は、単独では成立を主張できない。** 実装が無ければ
  何も起きないので当然満たされる。**「操作が実際に起きた」または「正しいエラーを
  出した」を同じケースの中で対にする。**

例: `I-X1`（他方のイメージがバイト不変）は「送信先が実際に変わった」と対にする。
`I-N*`（mtools を呼ばない）は「E2 が実測シリアルを出した」と対にする。

## 3. レベル配分の方針

| 水準 | 何を見るか | 道具 |
| --- | --- | --- |
| 静的 (S) | 構造の保証。grep で「そう書かれていない」ことを見る | `grep`・`bash -n`・`shellcheck`（あれば） |
| 単体 (U) | 関数単位。シリアル読み・選択の決定表・名前検証 | `source` して関数を直接呼ぶ（N1 が前提） |
| 統合 (I) | コマンド 1 回の起動。実イメージを作って状態を見る | `HOME` 砂場＋試験用イメージ |
| 入口 (A) | 引数解釈と終了コード | コマンド起動 |

**決定表は単体で張る。** 段 1・段 2 の 9 通りを統合で回すと、毎回イメージを作ることに
なって遅く、しかも「なぜ落ちたか」が状態からは読み取りにくい。

## 4. 静的 (S)

| | 見るもの | 根拠 |
| --- | --- | --- |
| **S1** | `bash -n 98hdd.sh` が通る | 構文 |
| **S2** | `main "$@"` が `BASH_SOURCE` の条件の内側にある | N1。これが崩れると単体試験が全滅する |
| **S3** | **ドライブ文字を組み立てる綴りが残っていない**（`"${HDD_DRIVE}:"`・`"$DRIVE"` を mtools 引数に渡す形） | 仕様 §3.8。1 箇所でも残ると、そこだけ `~/.mtoolsrc` を読む |
| **S4** | mtools の実行が `run_mtools` 以外から起きていない | N3。観測の穴を塞ぐ |
| **S5** | `run_mtools` に `MTOOLS_SKIP_CHECK=1` がある | §8 実測。外すと**全部落ちる**が、理由が分からない落ち方をする |
| **S6** | `@@` を含む綴りが `-i` の引数組み立て以外に無い | 誤った場所でオフセットを足す経路を防ぐ |
| **S7** | シリアルを読む位置の定数（`38`・`39`・`0x26`・`0x27`）が **1 箇所にまとまっている** | 2 箇所に散ると片方だけ直す欠陥が入る |
| **S8** | `mformat` を呼ぶ綴りが**製品コードに無い** | 仕様 §2 非目標（フォーマットしない）。ハーネスにはあってよい |

## 5. 単体 (U)

### 5.1 シリアル読み取り `read_serial <img> <off>`

| | 入力 | 期待 |
| --- | --- | --- |
| **U-S1** | `-N 11112222` で作ったイメージ | `1111-2222` を返し終了 0 |
| **U-S2** | `-N 0c010a1f` で作ったイメージ | `0C01-0A1F`（**実機と同じ値**。大文字で返すこと） |
| **U-S3** | `-N deadbeef` | `DEAD-BEEF`。バイト逆順が効いていることの検出器 |
| **U-S4** | 署名が `0x00` のイメージ | **E9 相当の失敗。シリアルを返さない** |
| **U-S5** | FAT32 イメージ | 同上（`0x26` が `0x29` でない） |
| **U-S6** | オフセットを 512 ずらした指定 | 同上。**誤ったオフセットが黙って通らない** |
| **U-S7** | ファイルがオフセットより短い | 同上。`od` が 0 バイト返す場合を失敗として扱う |
| **U-S8** | 同じイメージを 2 回読む | 同じ値（副作用が無い） |
| **U-S9** | 読んだあとイメージが**バイト不変** | 同定が読み取り専用であること |

**U-S3 が効く理由。** `11112222` のような対称に近い値だと、バイト順を間違えても
気づけない組み合わせがある。`deadbeef` は 4 バイトすべてが相異なるので、
逆順・部分逆順・上下ワード入れ替えのどれもが別の文字列になる。

### 5.2 カード名の検証 `valid_card_name <name>`

| | 入力 | 期待 |
| --- | --- | --- |
| **U-N1** | `main`・`games`・`card-2`・`a_b`・`A1` | 受理 |
| **U-N2** | `my card`（空白）・`カード`・`a/b`・`a.b`・`-`で始まる・空文字 | **拒否**（E7） |
| **U-N3** | `..` | 拒否。パス脱出の芽を摘む |

### 5.3 選択の決定表 `select_card`

仕様 §3.4・§3.5。入力は「定義の集合」「各 `IMAGE` の存在」「各イメージの実シリアル」
「`-c` の有無」。

| | 定義 | 存在 | シリアル一致 | `-c` | 期待 |
| --- | --- | --- | --- | --- | --- |
| **U-C1** | 0 枚 | — | — | 無 | 暗黙 `default`。照合しない |
| **U-C2** | 1 枚 | する | する | 無 | その 1 枚 |
| **U-C3** | 1 枚 | する | **しない** | 無 | **E4**（段 2 で 0 枚） |
| **U-C4** | 1 枚 | しない | — | 無 | **E4** |
| **U-C5** | 3 枚 | 1 つだけ | する | 無 | その 1 枚 |
| **U-C6** | **3 枚が同じパス** | する | **1 つだけ一致** | 無 | **その 1 枚。E3 にしない** |
| **U-C7** | 2 枚・別パス | 両方 | 両方一致 | 無 | **E3** |
| **U-C8** | 3 枚 | 0 つ | — | 無 | **E4** |
| **U-C9** | 3 枚 | 1 つ | **どれとも不一致** | 無 | **E4。読めたシリアルを文面に含む** |
| **U-C10** | 3 枚 | 2 つ | 両方一致 | **有**（3 つ目） | **指定どおり。段 1・段 2 を行わない** |
| **U-C11** | 3 枚 | — | — | **有**（未定義名） | **E6** |
| **U-C12** | 1 枚 | する | する | **有**（その名前） | その 1 枚 |

**U-C6 がこの設計の核心である。** BlueSCSI のカードを同じ手順で作れば全部同じパスに
なるので、これが**最も普通の構成**である。段 2 が無い実装はここで E3 を返す。
`U-C7` と対にすることで「同じパスで複数定義」と「別パスで複数マウント」を分けている。

**U-C10 は `-c` が段 1・段 2 を飛ばすことを見る。** 2 枚マウントされている状態で、
指定した 3 つ目（マウントされていない）を選ぶので、E3 にも E4 にもならず
**E1/E2 の側へ進む**ことで判別できる。

### 5.4 設定の読み込み `load_cards`

| | 入力 | 期待 |
| --- | --- | --- |
| **U-L1** | `IMAGE`・`OFFSET`・`SERIAL` が揃った `.conf` | 読める |
| **U-L2** | `SERIAL` が無い | **E8。欠けている変数名を言う** |
| **U-L3** | `OFFSET` が無い | E8 |
| **U-L4** | `IMAGE` が無い | E8 |
| **U-L5** | 名前に空白を含む `.conf` | **E7。読み飛ばさない** |
| **U-L6** | `PULL_DIR` 省略 | `<BASE_DIR>/hdd/<名前>` が入る |
| **U-L7** | `SEND_DIR` 省略 | グローバルの値が入る |
| **U-L8** | `.conf` が 0 個（ディレクトリは在る） | 暗黙 `default` へ落ちる |
| **U-L9** | ディレクトリ自体が無い | 暗黙 `default` へ落ちる |
| **U-L10** | 2 枚の `PULL_DIR` が同じ実パス（**片方はシンボリックリンク経由**） | **E5** |

## 6. 統合 (I)

`HOME` 砂場に `.98hddrc` と `.98hdd/cards/*.conf` を置き、試験用イメージを作って、
`98hdd` をコマンドとして起動する。

### 6.1 後方互換（最優先）

| | 筋書き | 期待 |
| --- | --- | --- |
| **I-B1** | `.98hdd/` 無し・`.98hddrc` に `HDD_IMAGE`/`HDD_OFFSET` → `ls` | 終了 0・一覧が出る |
| **I-B2** | 同上 → `pull` | 終了 0・展開先が **`<BASE_DIR>/hdd`**（`hdd/default` **ではない**） |
| **I-B3** | 同上 → `send` | 終了 0・イメージにファイルが入る |
| **I-B4** | 同上 | 暗黙経路に入ったことを述べる行が stdout にある |
| **I-B5** | `.98hddrc` に `HDD_DRIVE="p"` が残っている | エラーにならない |
| **I-B6** | `.98hddrc` の `HDD_OFFSET` が**実際に使われる** | 誤ったオフセットを書くと E9 で止まる。**現行は未使用なので、ここが現行と変わる唯一の点** |

**I-B6 を明示する理由。** 仕様 §3.2 は「現行と同じ振る舞い」と言うが、`HDD_OFFSET` が
未使用から使用に変わるので、**`~/.mtoolsrc` と `~/.98hddrc` で値が食い違っていた利用者は
挙動が変わる**。今まではズレていても動いていた。ここは「黙って壊れる」のではなく
E9 で止まるので受け入れるが、試験で明示して文書にも書く。

### 6.2 選択と同定

| | 筋書き | 期待 |
| --- | --- | --- |
| **I-S1** | カード 2 枚定義・両方存在・シリアル一致 → `ls` | **E3・終了 1。mtools ログが空** |
| **I-S2** | 同じパスを指す 2 定義・シリアルで 1 つに絞れる → `ls` | 終了 0・選んだ名前が出る |
| **I-S3** | `-c b` を指定し、挿さっているのは a → `pull` | **E2・終了 1。`hdd/b` が作られていない** |
| **I-S4** | I-S3 の文面 | カード名 `b`・期待シリアル・実測シリアル・**「a なら一致する」**を含む |
| **I-S5** | 何も存在しない → `pull` | E4・終了 1・定義名が全部出る |
| **I-S6** | 存在するがどの定義とも不一致 → `pull` | E4・終了 1・**実測シリアルが出る** |
| **I-S7** | 署名が `0x00` のイメージ → `ls` | E9・終了 1・**オフセットを疑えと述べる** |
| **I-S8** | FAT32 イメージ → `ls` | E9・終了 1 |

### 6.3 隔離（この機能の目的そのもの）

| | 筋書き | 期待 |
| --- | --- | --- |
| **I-X1** | カード a・b を定義。a へ `send` | **b のイメージが sha256 でバイト不変** |
| **I-X2** | a を `pull` したあと b を `pull` | `hdd/a` と `hdd/b` が別々に埋まり、互いのファイルが混ざらない |
| **I-X3** | a を `pull` → b を `pull` → a を `pull` | 2 回目の a で「変更なし」が出る（b の pull が a のミラーを汚していない） |
| **I-X4** | `PULL_DIR` が衝突する定義 → `pull` | **E5・終了 1。mtools ログが空** |
| **I-X5** | 1 回の `pull` で `-i` に渡った綴りが**ちょうど 1 種類** | I3。偽 mtools のログを集計 |

**I-X1 がこの機能の受け入れ条件である。** 他のどの表明が通っても、これが落ちたら
機能は目的を果たしていない。

### 6.4 照合前に何もしない（I1・I2）

偽 mtools を**遮る版**にして、エラー経路で mtools が 1 度も呼ばれないことを見る。

| | 筋書き | 期待 |
| --- | --- | --- |
| **I-N1** | E1（`IMAGE` 不在）→ `pull` | mtools ログが**空**・`PULL_DIR` が作られていない |
| **I-N2** | E2（シリアル不一致）→ `pull` | 同上 |
| **I-N3** | E3（曖昧）→ `send` | 同上・**どのイメージもバイト不変** |
| **I-N4** | E5（`PULL_DIR` 衝突）→ `pull` | 同上 |
| **I-N5** | E9（署名不正）→ `send` | 同上 |

**E2 のときに読み取りすら許さないのは仕様 I1 の要求である。** 「読むだけなら安全」に
見えるが、E2 の時点で**どのイメージを読んだのかが不確か**なので、出力を信じてよい根拠が無い。

### 6.5 選んだカードを必ず告げる（§3.4.1）

後置 `-c` を無視することの安全弁なので、**無視の決定と同じ強さで試験する**。

| | 筋書き | 期待 |
| --- | --- | --- |
| **I-A1** | 自動判定で `pull` | `カード: <名前>（自動判定）` が出る |
| **I-A2** | `-c` 指定で `pull` | `カード: <名前>（-c 指定）` が出る。**自動判定と文面が異なる** |
| **I-A3** | 暗黙 `default` で `pull` | `カード: default` と、`~/.98hddrc` 由来であることが出る |
| **I-A4** | `ls`・`send` でも出る | 3 つのコマンドすべてで出ること（`pull` だけに付けると `send` の誤爆が見えない） |
| **I-A5** | **行が出るのは最初の mtools 呼び出しより前** | 偽 mtools のログと stdout の順序を突き合わせる。後に出ると、読み書きが終わってから知ることになる |

**I-A5 を機械で見る理由。** 「告げる」だけでは安全弁にならない。**操作の前に**告げないと、
利用者が気づくのは書き終わったあとである。偽 mtools がログに追記するので、
stdout とログの前後関係を比べれば機械で押さえられる。

### 6.6 `card` コマンド

| | 筋書き | 期待 |
| --- | --- | --- |
| **I-C1** | 2 枚定義 → `card list` | 両方の名前・`IMAGE` の有無・`PULL_DIR` が出る。終了 0 |
| **I-C2** | `card list` 実行後 | **イメージがバイト不変**（読み取りのみ） |
| **I-C3** | 挿さっている状態で `card show a` | **実測シリアルが出る**（定義に貼れる形で） |
| **I-C4** | 定義が 0 枚で `card list` | 暗黙 `default` を 1 行で出す。終了 0 |
| **I-C5** | `card list` は E3 を出さない | 一覧は曖昧さと無関係。**選択を走らせない**こと |

**I-C5 を置く理由。** `card list` が選択経路を通ると、2 枚マウント中に一覧が見られなく
なる。一覧は「何が定義されているか」を見るもので、「どれを使うか」とは別の問いである。

## 7. 入口 (A)

| | 入力 | 期待 |
| --- | --- | --- |
| **A1** | `98hdd -c a pull` | `-c` が解釈され、`pull` が走る |
| **A2** | `98hdd pull -c a`（挿さっているのは b） | **`-c` は無視**（2026-11-16 ユーザー決定）。自動判定で b が選ばれ、終了 0。**ただし `カード: b（自動判定）` が stdout に出る** — これが無視の安全弁なので、出なければ落ちる |
| **A2b** | `98hdd send mydir /GAME -c a` | `-c a` は `$3`/`$4` に落ちて無視される。`cmd_send` は `$1`・`$2` のみ参照する（現行どおり） |
| **A2c** | `98hdd ls /DOS -c a` | 同様に無視。`cmd_ls` は `$1` のみ参照 |
| **A2d** | `98hdd send -c a`（送信元の位置に `-c`） | `-c` が送信元ディレクトリとして扱われ、**「送信元ディレクトリがありません: -c」で終了 1**。黙って通さない |
| **A3** | `98hdd -c` （値なし） | 終了 1・使い方を出す |
| **A4** | `98hdd card` （副コマンドなし） | `card list` と同じか、使い方を出す。終了は 0 か 1 で一貫 |
| **A5** | `98hdd fd <img>` に `-c` を付ける | **`fd` はカードと無関係**。`-c` があっても選択を走らせない（仕様 §2 非目標） |
| **A6** | `98hdd help` | 終了 0・`-c` と `card` の説明を含む |
| **A7** | 未知のコマンド | 終了 1（現行どおり） |

**A5 が効く理由。** `fd` は FDI イメージを引数で受け取るので、カードの選択・同定は
一切要らない。ここで選択を走らせると、カードが挿さっていないだけで `fd` が
使えなくなる。現行の利用者が困る経路である。

## 8. 何を試験しないか

- **実機の SD カード 2 枚での動作。** Mac 側の試験は作ったイメージで張る。
  実物での確認は受け入れ基準 F1・F2（ユーザー作業）。
- **エラー文面の「対処が実際に効くか」。** 自然文の正しさは機械オラクルを持たない。
  機械で押さえるのは ①必要な字句（カード名・シリアル・パス）が現れる
  ②E1〜E9 の文面が互いに異なる の 2 点だけ。残りは audit の人手レビュー項目。
- **同時実行。** 仕様 §6 で非対象。
- **カードの複製（同じシリアルの 2 枚）。** 仕様 §3.3 が「区別できない」と明記した
  振る舞いなので、試験は「同じシリアルの 2 定義は E3 になる」までを見る。
- **`mformat` の挙動そのもの。** ハーネスの道具であって被試験対象ではない。
  ただし §0 の実測は結果として `mformat` の挙動に依存するので、ハーネスが
  期待どおりのイメージを作れなかったら**ケースを走らせる前に止める**（§9 の H 系）。

## 9. ハーネスの前提検査 (H)

被試験対象ではなく、**試験が意味を持つ前提**。1 件でも落ちたらケースを走らせない。

| | 見るもの | 落ちたときの意味 |
| --- | --- | --- |
| **H1** | `mformat`・`mdir`・`mcopy`・`mmd`・`od` が在る | 走らせられない |
| **H2** | `make_image` が作ったイメージの `0x26` が `0x29` | ハーネスが FAT16 を作れていない |
| **H3** | `make_image` が作ったイメージの `0x36` が `FAT16` | 同上（FAT12 や FAT32 になっている） |
| **H4** | 指定したシリアルが `0x27` から読める | `-N` が効いていない |
| **H5** | 偽 mtools が `PATH` 先頭で実際に呼ばれる | **観測が空振りする。** これが落ちると I-N 系が全部「緑の空振り」になる |
| **H6** | `HOME` 差し替えが効き、実 `$HOME` に書かれていない | **利用者の設定を壊す。** 最も危険な失敗 |

**H5 と H6 は特に重要である。** どちらも「落ちているのに緑に見える」形の失敗で、
しかも H6 は試験が利用者の実環境を壊す。

## 10. 実装前に赤であることを確認する

試験は実装より先に書く。**赤いだけでは足りない** — 意図した表明が意図した理由で
落ちていることを確かめる。

1. **第 1 段**: 現行の `98hdd.sh` に対して走らせる。`card` コマンドも `-c` も無いので、
   A 系・I-C 系は「不明なコマンド」で落ちるはず。**S3（ドライブ文字が残っていない）が
   落ちること**を確認する — ここが落ちないなら検査が壊れている。
2. **第 2 段**: 後方互換の I-B 系は**現行実装でも通るはず**（まだ何も変えていないので）。
   通らないなら、ハーネスか期待値が間違っている。**この段が設計の検算になる。**
3. **第 3 段**: 捨てスタブで帰属を取る。たとえば段 2 を持たない `select_card`（段 1 だけで
   判定する版）を書いて、**`U-C6` と `I-S2` だけが落ちる**ことを見る。他が落ちるなら
   ケースが絡み合っている。
