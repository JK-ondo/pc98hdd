# 98hdd の複数カード対応

## 動機

データ保管を複数の SD カードに分けたい。98 が同時に認識するのは 1 枚のままで、
カードを挿し替えて使う。

## 現状の構造で複数枚にすると壊れる 3 点（2026-11-16 調査）

1. **書き込み先が二重管理で、実効値は `~/.98hddrc` の外にある。** 実際に読み書き
   されるのは `~/.mtoolsrc` の `drive p:` で、`HDD_IMAGE` は存在チェックにしか
   使われず、`HDD_OFFSET` は `SPEC.md` 自身が「現状未使用」と書いている。
   カードを替えるとき `~/.98hddrc` だけ直して `~/.mtoolsrc` を忘れると、
   **`check_image` は B で通り、mtools は A に書く**。1 枚のうちは起こり得ないので
   欠陥として現れていない。2 枚目を挿した日に fail-open になる。
2. **`hdd/` が 1 つしかない。** `PULL_DIR` 固定なので、カード B を pull すると
   A のミラーを上書きする。2026-11-16 に実際に起きた（フィクスチャ原本が上書きされ、
   `98hdd pull` の `.bak_<時刻>` 退避に救われた）。複数枚では退避名も由来を言わない。
   現状 1,878 ファイル / 41 MB が 1 つの籠に入っている。
3. **パスはカードを同定しない。** BlueSCSI 命名 `HD<ID><LUN>_<セクタ長>` は SCSI ID を
   表すだけ。1 枚ずつ挿す運用なら 2 枚とも `/Volumes/x/HD10_512 200MB.hda` になり得る。
   「今どれが刺さっているか」を知る手段が無い。

## 決定（2026-11-16 ユーザー承認）

1. **案 A ＋ B を採る。** カードごとにプロファイルを定義し、起動時に「挿さっているのは
   どれか」を自動判定する。合えば黙って進み、**食い違えば止める**。`-c <名前>` で明示
   指定もできる。打鍵は自動検出の短さで、安全性はプロファイルのものになる。
   - 採らなかった案 B 単独（自動検出のみ）: カードを名前で呼べないので `hdd/` の分け方に
     困り、2 枚挿したときに曖昧になる。
   - 採らなかった案 C（毎回 `--image` と `--offset` を打つ）: 問題 2 が残り、打鍵が長い。
2. **`hdd/` はカードごとに分ける。** 問題 2 の唯一の直し方。

3. **ただし既存の 1,878 ファイルは移さない（2026-11-16、仕様を書く段で決着）。**
   当初は「一度移す必要がある」と書いたが、**暗黙の `default` カード**で解ける。
   カードを 1 枚も定義していなければ `~/.98hddrc` の値から `default` を組み立て、
   `PULL_DIR` も従来どおり `hdd/` のままにする。`hdd/default/` にはしない。
   カードごとの分離は、利用者が 2 枚目を定義したときに初めて現れる。
   - **後方互換と移行が同じ 1 つの仕掛けで片付く。** 公開済みの道具なので、
     利用者に 41 MB の移動を課さずに済むことの価値が大きい。
   - 採らなかった案「一律 `hdd/<名前>/` へ移す」: 筋は通るが、既存利用者全員に
     一度きりの手作業を強いる。しかもその手作業は失敗すると 41 MB を失う。

## 使える梃子

`cmd_fd` が既に `~/.mtoolsrc` を使わず `-i "<img>@@<offset>"` ＋ `::` で書かれている
（98hdd.sh:327・341・344・374）。mtools 4.0.49 の機能で、**この家の既存の書き方**。
13 ある mtools 呼び出しのうち 3 つは既にこの形。

## 実測で決着した点（2026-11-16）

**`-i` 方式は PC-98 の HDD パーティションでも成立する。** ジオメトリは要らない。

| | `p:` 経由 | `-i` 経由 |
| --- | --- | --- |
| `mdir -s -b` のパス一覧 | 1,860 行 | 1,860 行・**全行一致** |
| 空き容量 | 155,729,920 B | 155,729,920 B |

**条件は `MTOOLS_SKIP_CHECK=1`。** 素の `mdir -i` は `Bad media types fe/f8` で落ちる。
`98hdd.sh:37` の `run_mtools() { MTOOLS_SKIP_CHECK=1 "$@"; }` が既にすべての呼び出しを
包んでいるので、**スクリプトの中では最初から条件が満たされている**。最初の試行が
落ちたのは、素の `mdir` で測ってスクリプトと同じ条件になっていなかったため。

したがって `~/.mtoolsrc` の `cylinders=820 heads=8 sectors=17` は読み取りには不要で、
依存を丸ごと切れる。設計は一番単純な形を採れる。

### 書き込みも通る

控えのイメージ（原本と sha256 一致、209,780,736 B）で測った。`mcopy -o` は 15 バイトを
バイト一致で往復し、`mmd -D s` も成功。増えたパスは**ちょうど 3 件**、消費は 4 KB
クラスタ **3 個**で、他に変化なし。FAT は壊れていない。

同定の鍵も実測した。ブートセクタ offset `0x27`（イメージの `<OFFSET>+39` バイト目）から
4 バイトを `od` で読むと `0C01-0A1F` で、`mdir` の言う値と一致する。**mtools を起動せず、
イメージ全体を走査せずに同定できる。**

## 仕様で決着した 5 点（詳細と採らなかった案は `spec.md`）

| 論点 | 決着 |
| --- | --- |
| 同定の鍵 | **FAT のボリュームシリアル番号**。`od` で 4 バイト。カードではなくイメージを同定するので、読み書きの対象と粒度が一致する |
| プロファイルの置き場 | `~/.98hdd/cards/<名前>.conf`。1 枚 1 ファイルでシェルとして source。`~/.98hddrc` はグローバル設定として残す |
| 既存利用者の移行 | **しない**（決定 3） |
| 後方互換 | 暗黙の `default` カードで解く（決定 3 と同じ仕掛け） |
| `send/` | 既定では分けない。プロファイルで上書きはできる。送信先を間違える危険は同定が塞ぐので、ステージング領域まで分ける見返りが小さい |

## 変えないもの

- 同時に挿すカードは 1 枚（98 側の制約であり、この道具の制約ではない）。
- `fd`（FDI 展開）と `pc98/` はカードと無関係なので触らない。
- 8.3 名変換・文字コード変換・`TEXT_EXTS` は今回の対象外。
