### 一度外した観測から学んだこと

最初の試行は `Bad media types fe/f8 / Error reading FAT / Cannot initialize '::'` で
落ちた。原因は**測り方**で、素の `mdir` を使ったため `98hdd.sh:37` の
`run_mtools() { MTOOLS_SKIP_CHECK=1 "$@"; }` と同じ条件になっていなかった。
`Bad media types` は**まさにその環境変数が黙らせている検査**である。

危なかったのは、この失敗をそのまま受け取ると「ジオメトリが必要」という**誤った結論**に
達し、設計が一段複雑な側（プロファイルにジオメトリを持たせ、一時 `MTOOLSRC` を生成する）
へ倒れていたこと。**道具の実際の呼び方を再現していない実測は、実測ではない。**

## 2026-11-16（試験設計）

### ハーネスの成立を先に測った

`98hdd.sh` には**試験がひとつも無い**ので、設計の前に「そもそも書けるか」を確かめた。

| 問い | 答え |
| --- | --- |
| 試験用の FAT16 イメージを作れるか | `mformat -i <img>@@<off> -T 32768 -N <serial> ::`。**作れる** |
| シリアルを指定できるか | `-N` で指定でき、`0x27` から読める |
| 実消費 | **496 KB**。`-T 16384` だと FAT12 になり**かえって 9.5 MB** 食う（クラスタが小さく FAT 表が巨大になる） |
| 利用者の環境を汚さずに書けるか | `BASE_DIR` と `CONFIG_FILE` が `${HOME}` からのみ派生。**`HOME` の差し替えで完全に隔離できる** |
| 関数単位で試験できるか | **できない。** 499 行目の `main "$@"` が無条件に走る |

### FAT32 の罠を踏んで、仕様の裏付けが増えた

最初 `mformat -F` で作ったら、`mdir` は `1111-2222` と言うのにブートセクタの `0x27` が
空だった。**mformat の `-F` は FAT32 を強制する**（FAT16 の指定ではない）。FAT32 では
署名が `0x42`、シリアルが `0x43` へ移る。

**副産物が 2 つ。** ①FAT32 の `0x26` は `FATSz32` の上位ワードで実測 `0x00` だったので、
仕様の E9（署名が `0x29` でなければ止める）が**FAT32 を自動的に弾く**。PC-98 DOS は
FAT32 を扱えないので、これは正しい振る舞いである。②試験の異常系イメージとして
FAT32 をそのまま使える。

### 試験設計が仕様の誤りを 1 つ暴いた

後方互換のケース（I-B6）を書いていて気づいた。仕様 §3.2 と不変条件 I4 は
「カード未定義の利用者の振る舞いは現行と同じ」と言い切っていたが、**`HDD_OFFSET` は
現行「未使用」で、この機能で実効値になる**。`~/.mtoolsrc` と `~/.98hddrc` で値が
食い違っていた利用者は、今までズレたまま動いていたのが、これからは `.98hddrc` の値が
使われる。

食い違えば FAT の先頭を指さないので **E9 で止まる**（黙って別の場所を読み書きしない）ので
受け入れるが、言い切りは誤りだった。§3.2・I4・受け入れ基準 A4 を直し、README に移行案内を
書くことを Done when に足した。

### 設計で特に効くと考えている 3 点

- **`U-C6`**（同じパスを指す 3 定義がシリアルで 1 つに絞れる）が段 2 の有無を分ける
  唯一の検出器。段 2 を持たない実装はここだけが落ちる。
- **`I-N` 系**（照合前に mtools を呼ばない）は、偽の mtools を `PATH` 先頭に置いて
  **呼び出しが起きなかったこと**を見る。結果の状態を見るだけでは張れない。
- **`H5`・`H6`**（偽 mtools が実際に呼ばれる／`HOME` 差し替えが効く）は、落ちると
  「緑の空振り」になる前提検査。特に `H6` が落ちると**試験が利用者の実環境を壊す**。

## 2026-11-16（後置 `-c` の決着と実装計画）

### 未決 1 件が解けた

ユーザーが「`98hdd pull -c a` のように後ろに置いた `-c` は無視していい」と決めた。

実装上は**ほぼ無料**だと分かった。`cmd_send` は `$1`・`$2` のみ、`cmd_ls` は `$1` のみを
参照するので、後ろに付いた余分な引数は既に落ちている。`98hdd send -c a` のように
送信元の位置に書いた場合は「送信元ディレクトリがありません: -c」で終了 1 になり、
黙って通ることもない。

**ただし残る帰結を 1 つ塞いだ。** 無視すると自動判定が走るので、`-c a` と打って
b が挿さっていれば b を扱う。データは壊れない（シリアルで同定済みで、行き先も b 自身の
`PULL_DIR`）が、頼んだものとは違う。そこで仕様 §3.4.1 に
**「選んだカードを操作の前に必ず名前で告げる」**を足した。これが無視の安全弁である。

試験もそれに合わせて強めた（§6.5、5 ケース）。特に **`I-A5`「告げるのは最初の mtools
呼び出しより前」** を偽 mtools のログと stdout の順序で機械的に押さえる — 後に出ると、
利用者が気づくのは書き終わったあとになる。ケース数は 78 → **88**。

### 実装計画（`impl-plan.md`、T1〜T16）

変換で一番危ない箇所を特定した。**`cmd_pull` は `mdir` の出力を `sed` で解析している**。

| | 現行 | 変換後 |
| --- | --- | --- |
| 243 行 | ドライブ接頭辞ごと小文字化（`P:/X` → `p:/x`） | そのまま（`::` は英字を含まない） |
| **255 行** | `rel=$(echo "$hdd_path" \| sed "s\|^${HDD_DRIVE}:/\|\|i")` | **`rel="${hdd_path#::/}"`** |

`cmd_fd` が既に後者の書き方（360 行）なので、形を揃えるだけ。
**副産物: 1,878 ファイルぶんの `sed` 起動が消える。**
