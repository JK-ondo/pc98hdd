### FAT32 の罠を踏んで、仕様の裏付けが増えた

最初 `mformat -F` で作ったら、`mdir` は `1111-2222` と言うのにブートセクタの `0x27` が
空だった。**mformat の `-F` は FAT32 を強制する**（FAT16 の指定ではない）。FAT32 では
署名が `0x42`、シリアルが `0x43` へ移る。

**副産物が 2 つ。** ①FAT32 の `0x26` は `FATSz32` の上位ワードで実測 `0x00` だったので、
仕様の E9（署名が `0x29` でなければ止める）が**FAT32 を自動的に弾く**。PC-98 DOS は
FAT32 を扱えないので、これは正しい振る舞いである。②試験の異常系イメージとして
FAT32 をそのまま使える。

### 試験設計が仕様の誤りを 1 つ暴いた

後方互換のケース（I-B6）を書いていて気づいた。仕様 §3.2 と不変条件 I4 は
「カード未定義の利用者の振る舞いは現行と同じ」と言い切っていたが、**`HDD_OFFSET` は
現行「未使用」で、この機能で実効値になる**。`~/.mtoolsrc` と `~/.98hddrc` で値が
食い違っていた利用者は、今までズレたまま動いていたのが、これからは `.98hddrc` の値が
使われる。

食い違えば FAT の先頭を指さないので **E9 で止まる**（黙って別の場所を読み書きしない）ので
受け入れるが、言い切りは誤りだった。§3.2・I4・受け入れ基準 A4 を直し、README に移行案内を
書くことを Done when に足した。

- **`U-C6`**（同じパスを指す 3 定義がシリアルで 1 つに絞れる）が段 2 の有無を分ける

- **`I-N` 系**（照合前に mtools を呼ばない）は、偽の mtools を `PATH` 先頭に置いて

## 2026-11-16（後置 `-c` の決着と実装計画）

### 未決 1 件が解けた

ユーザーが「`98hdd pull -c a` のように後ろに置いた `-c` は無視していい」と決めた。

実装上は**ほぼ無料**だと分かった。`cmd_send` は `$1`・`$2` のみ、`cmd_ls` は `$1` のみを
参照するので、後ろに付いた余分な引数は既に落ちている。`98hdd send -c a` のように
送信元の位置に書いた場合は「送信元ディレクトリがありません: -c」で終了 1 になり、
黙って通ることもない。

**ただし残る帰結を 1 つ塞いだ。** 無視すると自動判定が走るので、`-c a` と打って
b が挿さっていれば b を扱う。データは壊れない（シリアルで同定済みで、行き先も b 自身の
`PULL_DIR`）が、頼んだものとは違う。そこで仕様 §3.4.1 に
**「選んだカードを操作の前に必ず名前で告げる」**を足した。これが無視の安全弁である。

試験もそれに合わせて強めた（§6.5、5 ケース）。特に **`I-A5`「告げるのは最初の mtools
呼び出しより前」** を偽 mtools のログと stdout の順序で機械的に押さえる — 後に出ると、
利用者が気づくのは書き終わったあとになる。ケース数は 78 → **88**。

### 実装計画（`impl-plan.md`、T1〜T16）

変換で一番危ない箇所を特定した。**`cmd_pull` は `mdir` の出力を `sed` で解析している**。

| | 現行 | 変換後 |
| --- | --- | --- |
| 243 行 | ドライブ接頭辞ごと小文字化（`P:/X` → `p:/x`） | そのまま（`::` は英字を含まない） |
| **255 行** | `rel=$(echo "$hdd_path" \| sed "s\|^${HDD_DRIVE}:/\|\|i")` | **`rel="${hdd_path#::/}"`** |

`cmd_fd` が既に後者の書き方（360 行）なので、形を揃えるだけ。
**副産物: 1,878 ファイルぶんの `sed` 起動が消える。**

`sut_eval` は被試験対象を source して断片を eval する。**`main "$@"` が無条件に

### bash 3.2 の制約が実装の形を決めた

macOS の bash は **3.2.57 で連想配列が使えない**（`98hdd.sh:184` が既にこの前提を
書いていた）。カードの集合を持ち回る形を**行指向**に決め、仕様 §3.1.1 として
明文化した。

```
load_cards  → 1 枚 1 行で name|image|offset|serial|pull_dir
select_card → 選んだ 1 枚の同じ形式の行
```

並行する添字配列は採らない。枚数と添字の対応を手で保つ必要があり、1 箇所ずれると
**別のカードの `IMAGE` に別のカードの `SERIAL` を当てる**経路ができる。

### 試験を書いて仕様の穴を 1 つ見つけた

カード名の規則が `[A-Za-z0-9_-]+` だったので、**`-x` という名前が通ってしまう**。
`98hdd -c -x pull` のような呼び方が生まれ、引数解釈が名前とオプションを区別
できなくなる。1 文字目を `[A-Za-z0-9]` に絞った（仕様 §3.1）。

照合ごと飛ばしていたので、`HDD_OFFSET` が誤っていても mtools の
`non DOS media` という不親切な失敗になっていた。**署名の確認は「この位置に
FAT があるか」の話で同定とは別**なので、`SERIAL` の有無に関わらず行う形へ直した。

**② 自動判定で「イメージは在るが FAT として読めない」が「カードが見つからない」に
化けていた**（`I-S7`・`I-S8`）。カードは挿さっているのにそう言うのは誤解を招く。
読めない候補があればそちらを E9 で述べる形へ直した。

### 実機の控え（200 MB・本物の表）で実地確認した

| | 結果 |
| --- | --- |
| `card list` | `real 一致` |
| 自動判定 | `カード: real（自動判定）` |
| 名前間違い | E6・終了 1 |
| **シリアルを偽る** | **「この値はカード real のものです。-c real なら一致します。」** |
| 同じパスの 2 定義 | 1 枚に絞れた |
| オフセット間違い | E9・実測署名 `0x00` |
| **本物の規模で pull** | **1,790 ファイル・イメージはバイト不変** |

16 MB の試験用イメージではなく本物の表で通ることを見た。

### 帰属（T12）— 10 本の変異に全部殺し手が居る

### 帰属が試験の弱点を 2 つ暴いた

**`I-A5` が弱い検出器だった。** 告知を操作の後へ動かしても通ってしまった —
針を「カード名」にしていたので、`cmd_pull` の「展開先: …/hdd/alpha」という
別の行に当たっていた。**針を告知の行そのもの（`カード: `）へ**直した。

**M5（シリアル漏れ）に殺し手が居なかった。** `U-L2`（SERIAL 欠落）は 1 枚しか
置かないので漏れる元が無い。**`U-L11` を足した**（1 枚目に SERIAL があり
2 枚目に無い構成）。これで 16 件が殺すようになった。

NX93 の T11 と同じ経験で、**帰属を取らないと「緑だが見ていない」試験が残る**。

### 簡素化の候補として記録

`M4` の殺し手が 1 件なのは欠陥ではなく、`use_card` の `verify_card` 呼び出しが
`-c` 経路（`select_card` の中で既に照合済み）と自動経路（段 2 で絞り済み）では
**冗長**で、暗黙 `default` だけが唯一の担当経路だから。残す必要はあるが、
`-c` 経路の二重照合は code-simplifier に見せる価値がある。

## 2026-11-17（T15 — 監査）

Agent を呼ばない指示があるので、`audit` の検査項目を自分で回した。
**指摘 6 件。全部その場で直した。** 91 ケース全部緑（217 表明）。

### 欠陥 3 件 — 根はどれも同じだった

`load_cards` が値の**有無**は見るが**形**を見ていなかった。仕様 §3.1 は形を
定めているのに、実装は非空しか確かめていない。形が違うと、下流で**別の症状に
化けて**出る。

| | 実測した症状 |
| --- | --- |
| `OFFSET` が数値でない | **bash の生エラーが利用者の画面に漏れる**（`line 97: abc: unbound variable`）。算術展開が `set -u` 下で落ちる |
| `SERIAL` が `XXXX-XXXX` でない | 「カード ser ではありません」と報告され、**書式の誤りが取り違えに化ける** |
| パスに `\|` が入る | 行の区切りと衝突して値が切れ、「使えるカードが見つかりません」という**無関係な文面**になる |

3 つとも `load_cards` に形の検査を足して直した。`read_boot_signature` にも
`read_serial` と同じ番兵を置いた（防御の二重化）。

**区切り文字の検査は分割の前に置く必要があった。** 最初は分割後に `case` で
見ていたが、`|` が入ると既に値がずれているので「`OFFSET` が数値でない」が先に
発火して誤りの在りかを隠した。試験（`U-L14`）がそれを捕まえた。生の文字列で
`|` を数える形（4 欄なのでちょうど 3 個）に直した。

### 構造 3 件

- **`check_image` が死にコードだった。** `use_card` の照合が役目を引き継いだので
  呼び出しが 1 つも残っていなかった。削除。
- **`load_cards` が 1 回の起動で 2 回走っていた。** `use_card` が
  `verify_card "$line" "$(load_cards)"` と呼んでいたが、**第 2 引数（一覧）が
  使われる経路が無い**。一覧は「一致するカードを名指す」ためだけに使われ、
  ここへ来る 3 経路はいずれもそこへ到達しない（`-c` は `select_card` の中で
  一覧つきの照合を済ませ、自動経路は段 2 で一致済み、暗黙 `default` は
  `SERIAL` が無いので署名の確認で終わる）。空を渡す形にして、設定の二度読みを
  やめた。
- **E3 の枝でシリアルを読み直していた。** 段 2 の最中に名前を集める形に直した。
