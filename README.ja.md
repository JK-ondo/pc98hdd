# pc98hdd — PC-98 アーキテクチャ機と Mac のファイル受け渡し

*English: [README.md](README.md)*

BlueSCSI の microSD を持ち運ぶことで、PC-98 アーキテクチャの実機と Mac の間でファイルを
やり取りするための道具一式です。SD カードを差し替えるだけで、Mac から 98 へファイルを送り、
98 の HDD の中身を Mac に吸い上げられます。5 インチ / 3.5 インチ FD のデータも、98 を
中継すれば運べます。

操作はすべて `98hdd` という 1 本のコマンドで行います。

```
[5" / 3.5" FD] ⇄ [PC-98 実機] ⇄ [BlueSCSI] ⇄ [microSD]
                                     │  ← 電源を切って SD を抜き、Mac に挿す
                                     ▼
                                [Mac /Volumes/x]
                                98hdd send / pull
```

より詳しい内部仕様は [SPEC.md](SPEC.md) にあります。ここは使い方だけです。

## 1. 必要なもの

### ハードウェア

| 機器            | 備考                                              |
| --------------- | ------------------------------------------------- |
| PC-98 実機      | 下の対応機種を参照                                |
| BlueSCSI v2     | SCSI ID 1 / LUN 0 / 512 bytes-per-sector で運用中 |
| microSD カード  | Mac に挿すとボリューム名 `x` でマウントされること |
| Mac             | ここで `98hdd` を動かす。macOS 専用(Apple Silicon で開発) |

#### 対応機種

Mac 側の道具は HDD イメージの中の FAT16 しか見ていないので、98 の機種には依存しません。
とはいえ実機で確かめた範囲は次のとおりです。

| 機種              | 状態       |
| ----------------- | ---------- |
| NEC PC-9801RS     | 確認済み   |
| NEC PC-9821Ra7    | 確認済み   |
| EPSON PC-486GR    | 確認済み   |

同じ条件(BlueSCSI + 日本語 MS-DOS + FAT16)を満たす他の PC-98 アーキテクチャ機でも
動くはずですが、**未検証**です。

SD カード上の HDD イメージは `HD10_512 200MB.hda`(200MB / FAT16 1 パーティション)です。
ファイル名の `HD10_512` は BlueSCSI の命名規約なので、**リネームすると 98 から見えなくなります**。

### Mac 側のコマンド

`98hdd` は起動時に以下の存在を確認し、1 つでも欠けると何もせず終了します。

- `mdir` `mcopy` `mmd` — mtools
- `nkf` — 文字コード変換
- `iconv` `file` — macOS 標準

mtools と nkf が入っていない場合は Homebrew などで導入してください(`mtools` と `nkf` の 2 つ)。

### Windows について

**これは macOS 向けの道具です。Windows は未確認です。**

ただしスクリプトの中身に macOS 固有のものはほとんどありません。イメージのパスは
`~/.98hddrc` で上書きできる既定値にすぎず、呼んでいるコマンドはすべて POSIX の範囲です。
WSL2 に `mtools` と `nkf` を入れ、`HDD_IMAGE` と `~/.mtoolsrc` の `file=` を SD カード
(`/mnt/e/...`)へ向けて `mount -t drvfs` でマウントすれば、おそらく動きます。先に
引っかかるのは次の 2 点です。

- **改行コード。** Windows の Git は既定が `core.autocrlf=true` なので、シェルスクリプトが
  CRLF で展開され、bash が `$'\r': command not found` で死にます。`.gitattributes` で
  木全体を LF に固定してあるのは、これを防ぐためです
- **`98hdd` はシンボリックリンク。** `core.symlinks=true` でないと Git は代わりに 9 バイトの
  テキストファイルを置くので、`./98hdd` は動きません。`bash 98hdd.sh` を使ってください

とはいえ Windows なら別の道具のほうが素直です。**DiskExplorer** は PC-98 のディスク
イメージを GUI で直接読み書きできますし、ImDisk や OSFMount なら `offset=360448` を
指定してドライブレターに割り当てられます。

## 2. 初回セットアップ

### 2-1. ディレクトリと設定ファイルを作る

`98hdd.sh` は既定の作業場所を `~/9801` と決め打ちしています。そこへ置くのが一番手数が
少ないので、まずそこに clone します。

```sh
git clone https://github.com/JK-ondo/pc98hdd.git ~/9801
cd ~/9801
./98hdd init
```

`send/` `hdd/` と設定ファイル `~/.98hddrc` が作られます(既にあれば何もしません)。

別の場所に置きたい場合は、clone 先はどこでも構いません。`98hdd init` のあとで
`~/.98hddrc` の `BASE_DIR` をその場所に書き換えてください。

### 2-2. `~/.mtoolsrc` を用意する

**これが無いと動きません。** mtools に「イメージファイルのどこから FAT16 が始まるか」を
教える設定です。以下の内容で `~/.mtoolsrc` を作成します。

```
drive p:
    file="/Volumes/x/HD10_512 200MB.hda"
    offset=360448
    fat_bits=16
    cylinders=820
    heads=8
    sectors=17
    filter
```

> **注意:** `offset` の実効値はこの `~/.mtoolsrc` だけです。`~/.98hddrc` にも `HDD_OFFSET`
> という項目がありますが現在は使われていません。HDD イメージを別のものに替えるときは、
> **両方のファイルを直す**必要があります。

### 2-3. 動作確認

SD カードを Mac に挿した状態で:

```sh
./98hdd ls
```

98 の HDD のルートのファイル一覧が出れば成功です。

## 3. 日常の使い方

### まず: SD カードの差し替え手順

Mac 側の操作は、いずれも **SD カードが Mac にマウントされている状態**で行います。

1. 98 の **電源を切る**
2. BlueSCSI から microSD を抜く
3. Mac に挿し、`/Volumes/x` にマウントされたことを確認
4. 以下のコマンドを実行
5. Finder で SD を取り出し(アンマウント)、BlueSCSI に戻す
6. 98 の電源を入れる

> ⚠️ **98 が動いている間に同じ SD を Mac から触らないでください。** 物理的に同時に
> 挿さることはありませんが、そこだけが安全装置です。ツール側に排他制御はありません。

### 3-1. Mac → 98 にファイルを送る

送りたいファイルを `send/` に置いてから:

```sh
./98hdd send
```

`send/` 以下のディレクトリ構造がそのまま HDD のルートに再現されます。

送信元・送信先を指定することもできます:

```sh
./98hdd send pc98/DOS62 /FD/DOS62     # pc98/DOS62/ の中身を A:\FD\DOS62\ へ
```

送信は **全部成功するか、何も送らないか**のどちらかです。ファイル名の衝突か容量不足が
見つかった時点で、1 バイトも書かずに停止します。

### 3-2. 98 → Mac に吸い上げる(待避)

```sh
./98hdd pull
```

HDD 上の全ファイルが `hdd/` 以下に展開されます。最後に「新規 / 更新 / 変更なし」の件数が
出ます。

- 中身が前回と同じファイルは何もしません
- 中身が変わっていたファイルだけ、元のファイルを `<名前>.bak_20260907_153515` の形で
  退避してから置き換えます
- 取り出しに失敗したファイルは警告を出して飛ばします。**既存の `hdd/` の中身は壊れません**

> `pull` は追記型です。98 側で消したファイルは `hdd/` に残り続けます。

### 3-3. HDD の中を見る

```sh
./98hdd ls          # ルート
./98hdd ls /QC      # A:\QC の中身
```

### 3-4. FD イメージ(FDI)を展開する

`pc98/` にある Anex86 形式の FD イメージから、中のファイルを取り出します。
SD カードも HDD も関係なく、マウント不要で動きます。

```sh
./98hdd fd pc98/DOS62.FDI              # → pc98/DOS62/ に展開
./98hdd fd pc98/DOS62.FDI /tmp/out     # 出力先を指定
```

FAT でないイメージ(ゲーム独自フォーマットなど)はエラーを出して止まります。
**イメージファイル自体には手を触れません**。

### 3-5. FD とやり取りする

FD と Mac は直接つながりません。98 を中継点にします。

- **FD → Mac**: 98 上で `COPY B:\*.* A:\待避先` → SD を Mac へ → `98hdd pull`
- **Mac → FD**: `98hdd send` で HDD に送る → SD を 98 へ → 98 上で `COPY A:\... B:\`

## 4. 知っておくべき癖

### ファイル名は 8.3 形式に潰される(送信時)

送信時、ファイル名は次の規則で変換されます。

1. 大文字化する
2. `A-Z 0-9 _ -` 以外の文字を**捨てる**
3. ベース名 8 文字・拡張子 3 文字で切る

```
myLongName.c  →  MYLONGNA.C
```

⚠️ **日本語だけのファイル名は変換すると空になり、衝突エラーで停止します。**
送信前に ASCII 名へリネームしてください。
(逆方向の `pull` は、98 側の日本語ファイル名を UTF-8 に復元して展開できます。)

### テキストファイルは自動で文字コード変換される

| 方向   | 変換                                    |
| ------ | --------------------------------------- |
| `send` | UTF-8 + LF → Shift-JIS + CR+LF          |
| `pull` | Shift-JIS + CR+LF → UTF-8 + LF          |

テキストかどうかは**拡張子だけ**で決まります。以下が対象:

```
bat txt doc c h asm inc ini def bas err log md
```

これ以外はすべて無変換のまま運ばれます。

この設計は意図的なものです。以前は `file` コマンドで中身から判定していましたが、判定が
揺れて実行ファイルを壊した事故があったため、拡張子を明示する方式に変えました。

**この結果、2 つの帰結があります:**

- 上のリストに無い拡張子のテキスト(例: `.asm` 以外の設定ファイル)は Shift-JIS のまま
  `hdd/` に置かれます。中身は無傷なので、読むときは `nkf -w ファイル名` を通してください
- 上のリストに載っている拡張子のファイルは、**送って吸い上げると元のバイト列に戻るとは
  限りません**。リスト外のファイルは常にバイト単位で同一です

### `hdd/` は起動可能なバックアップではない

`mdir` が隠し属性のファイルを列挙しないため、`IO.SYS` / `MSDOS.SYS` などは `pull` されません。
`hdd/` は「**見えるファイルのミラー**」であって、ここから HDD を再構成しても 98 は起動しません。

## 5. 困ったとき

| 症状                                       | 原因と対処                                                                          |
| ------------------------------------------ | ----------------------------------------------------------------------------------- |
| `コマンドが見つかりません: mdir`           | mtools 未導入。`nkf` も同様                                                         |
| `HDDイメージが見つかりません`              | SD が `/Volumes/x` にマウントされていない。差し直すか、`~/.98hddrc` のパスを確認      |
| `ls` が何も出ない / 文字化けする           | `~/.mtoolsrc` が無いか `offset` が違う。2-2 を確認                                  |
| `ファイル名の衝突: ... → /XXX.C`           | 8.3 に潰すと同名になるファイルがある。片方をリネームして再実行(まだ何も送られていない) |
| `容量不足: 必要 N / 空き M bytes`          | 送るものを減らすか、98 側で不要ファイルを消す(まだ何も送られていない)                |
| `FATとして読めません（非DOSフォーマット?）` | そのイメージはゲーム独自フォーマット。`98hdd fd` の対象外                             |
| `コピー失敗: ...（スキップ）`              | その 1 ファイルだけ飛ばされた。他は正常。`hdd/` の既存ファイルは無事                 |

## 6. ディレクトリの中身

clone するとこれだけが入っています。

```
~/9801/
├── 98hdd            → 98hdd.sh へのシンボリックリンク(こちらを叩く)
├── 98hdd.sh         ツール本体
├── README.md        英語版
├── README.ja.md     このファイル
├── SPEC.md          詳細仕様書
├── LICENSE          MIT
├── mise.toml        検査タスク(mise run verify)
└── nx93rank/        おまけ: NyaHaX'93 のランキングを定期リセットする DOS 用プログラム
    └── docs/        その契約・決定記録・試験設計
```

残りは使っていくうちに手元にできるもので、リポジトリには入りません(`.gitignore` 済み)。

```
├── send/            Mac → 98 の送信置き場。ここに入れて 98hdd send
├── hdd/             98 → Mac の待避先。98hdd pull がここへ展開する
├── pc98/            FD イメージ(FDI)とソフトウェアの置き場
└── tools/           98 実機側で使うツール(HDD 完全複写ツールなど)
```

`send/` と `hdd/` は `98hdd init` が作ります。`pc98/` と `tools/` は自分で作ってください。

設定ファイルは `~/.98hddrc`(ツールの設定)と `~/.mtoolsrc`(イメージの読み方)の 2 つで、
どちらもリポジトリの外にあります。

## 7. 98 側の環境(作者の場合)

道具がこれを要求するわけではありません。動かしている相手がどういう環境かという参考です。

| 項目         | 内容                                                           |
| ------------ | -------------------------------------------------------------- |
| OS           | 日本語 MS-DOS Ver 5.0 基本機能セット(NEC)                      |
| 起動ドライブ | `A:`(BlueSCSI の HDD イメージ)                                 |
| 起動後       | `AUTOEXEC.BAT` が MOUSE を常駐 → DOSSHELL を起動               |
| `A:\DOS`     | MS-DOS ユーティリティ一式                                      |
| `A:\QC`      | Microsoft QuickC。`QC.EXE`(統合環境)/ `QCL.EXE`(コマンドライン) |

アセンブラ(MASM)は入っていません。

## 8. 入っていないもの

この道具が運ぶ中身は、どれもこのリポジトリには含めていません。

- MS-DOS 本体と添付ユーティリティ、Microsoft QuickC — NEC と Microsoft の著作物
- 市販ゲーム・同人ゲームの FD イメージやディスクの中身 — 各権利者の著作物
- 98 実機側で使う他者製ツール — 配布元から各自で入手してください
- `hdd/` に溜まる実機ミラー — 作者の手元のデータ

公開しているのは `98hdd.sh` とその文書、`nx93rank/`、検査タスクだけです。
BlueSCSI の HDD イメージそのものも含みません。自分の 98 のイメージを用意してください。
