# テスト計画（98hdd 複数カード対応）

`98hdd.sh` の Mac 側回帰テスト。**ケース 91 件 ＋ 前提検査 7 件。**

```sh
cd tests
./run-cards.sh              # 全ケース
./run-cards.sh -v           # ケース名を一件ずつ出す
./run-cards.sh -k U-C       # 名前に U-C を含むケースだけ
./run-cards.sh -k I-X1      # 隔離のケースだけ
```

依存は `bash`・`mformat`・`mdir`・`mcopy`・`mmd`・`od`・`shasum`・`dd` のみ。
ネットワークも追加インストールも使わない。全体で 1 分ほど。

**実機のカードには一切依存しない。** 試験用の FAT16 イメージをその場で作る。

オラクルは仕様（`.work/plans/98hdd-multi-card/spec.md`）を手で実行して導出した
もので、実装から採っていない。ケース名は同ディレクトリの `test-design.md` の
番号に対応する。

## 構成

| ファイル | 役割 |
| --- | --- |
| `run-cards.sh` | 前提検査 `H1`〜`H7` と静的検査 `S1`〜`S8`。下位スイートを source する |
| `lib/harness.sh` | 表明・砂場・イメージ生成・偽 mtools・`sut_eval` |
| `unit.sh` | `U-S`（シリアル読み取り）/ `U-N`（名前）/ `U-L`（設定）/ `U-C`（選択） |
| `integration.sh` | `I-B`（後方互換） |
| `select.sh` | `I-S`（選択と同定） |
| `isolate.sh` | `I-X`（隔離）/ `I-N`（照合前に何もしない） |
| `announce.sh` | `I-A`（カードを告げる）/ `I-C`（`card` コマンド） |
| `cli.sh` | `A`（コマンドとして起動） |

**下位スイートは `source` する**（別プロセスで起動すると件数が集計されない）。
そのため下位スイートに `exit` を書いてはいけない — ランナーごと終わって残りが
走らなくなる。

## ハーネスの仕組み

### 砂場（`HOME` の差し替え）

`98hdd.sh` の `BASE_DIR` と `CONFIG_FILE` は `${HOME}` からのみ派生するので、
`HOME` を差し替えるだけで設定・`hdd/`・`send/` がまとめて隔離される。

**前提検査 `H6` が毎回それを確かめる。** 落ちると試験が利用者の設定を壊すので、
1 件でも落ちたらケースを走らせずに終わる。`H6` は「砂場に書かれた」だけでなく
「実 `$HOME` が動いていない」も見る — 設定ファイルが実 `$HOME` に無い環境では
ハッシュの前後比較が空文字どうしになって無条件に通るので、存在の有無で場合を
分けてある。

### 試験用イメージ

```sh
make_image "$path" "11112222"   # FAT16・署名 0x29・指定シリアル・実消費 496 KB
```

オフセット 360448（実機と同じ）の先に FAT16 パーティションを 1 つ作る。
**オフセット 0 を既定にしない** — `@@` を落とす欠陥が試験を通ってしまう。

`-T 32768` で FAT16 になる。`-T 16384` だと FAT12 になり、クラスタが小さいぶん
FAT 表が巨大化して実消費がかえって増える（実測 9.5 MB）。

異常系は `make_bad_sig`（署名 `0x00`）・`make_fat32`（署名の位置が `0x42` へ
移る）・`make_truncated`（オフセットより短い）。

> **`mformat -F` は FAT32 を強制する**（FAT16 の指定ではない）。これを踏んで
> 一度ハーネスが FAT32 を作った。FAT32 では署名が `0x42`、シリアルが `0x43` に
> 移るので、`0x27` を読むと空だった。前提検査 `H2`・`H3` がこれを捕まえる。

### シリアル読み取りの独立実装

`read_serial_ref` は被試験対象の `read_serial` とは**別に書いてある**。同じコードを
両側に置くと、誤りが両側で打ち消し合って何も検証しない。

### 偽 mtools

`$scratch/bin` を `PATH` 先頭に置く。引数をログへ追記し、2 形ある。

| 形 | 動作 | 用途 |
| --- | --- | --- |
| 通す版 | 記録して本物へ `exec` | 状態が実際に動くケース |
| 遮る版 | 記録して終了 0 | **呼び出しが起きなかったこと**を見るケース（`I-N`） |

**前提検査 `H5` が「偽 mtools が実際に呼ばれる」ことを確かめる。** これが落ちると
`I-N` 系が全部「緑の空振り」になる — 呼ばれていないのに「ログが空」を満たして
しまい、落ちていることが結果から見えない。

### 終了コードの取り方

```sh
run_98hdd "$scratch" ls
assert_exit "..." 0 "$h_last_status"
assert_contains "..." "HELLO" "$h_last_output"
```

**`out=$(run_98hdd ...)` と書いてはいけない。** サブシェルで走るので
`h_last_status` が親へ伝わらず、`assert_exit` がひとつ前の呼び出しの古い値を見る。
一度この欠陥を作った（期待 1 のところ 99 のまま）。**前提検査 `H7`** がこの経路の
健全性を見る。

### 関数を直接呼ぶ

```sh
sut_eval "$scratch" "read_serial '$img' $HARNESS_OFFSET"
```

被試験対象を source して断片を eval する。`main "$@"` が `BASH_SOURCE` の条件で
包まれているので source しても何も実行されない。

## 否定の表明には必ず肯定の相方を付ける

実装中に**同じ型の欠陥を 3 回作った**ので、規約として書く。

| 出た形 | なぜ通ってしまったか |
| --- | --- |
| `assert_ne "exit" 0` | 関数が未実装なら `127` で、これも「非ゼロ」を満たす |
| `assert_contains "a"` | 1 文字の針は `bash: line 3: load_cards: command not found` に当たる |
| 「終了 1・行き先が無い・mtools が呼ばれていない」 | `-c` が未実装なら「不明なコマンド」で落ち、3 つとも満たす |

- **終了コードは「ちょうど 1」を要求する。** 仕様が語彙を {0,1} に限っているので、
  「非ゼロ」では未実装の `127` と区別できない。
- **針は識別力のある綴りにする。** カード名は `alpha`・`bravo`・`charlie` を使う。
- **不変性・不在・無呼び出しの表明は単独では成立を主張できない。** 実装が無ければ
  何も起きないので当然満たされる。**「操作が実際に起きた」または「正しいエラーを
  出した」を同じケースの中で対にする。**

例: `I-X1`（他方のイメージがバイト不変）は「送信先が実際に変わった」と対にする。
`I-N*`（mtools を呼ばない）は「E2 が実測シリアルを出した」と対にする。

## 帰属（どのケースがどの欠陥を殺すか）

被試験対象は `SUT_98HDD` で差し替えられる。

```sh
SUT_98HDD=/tmp/mutant.sh ./tests/run-cards.sh -v
```

13 本の捨てスタブを当てて測った結果（2026-11-17）。全部に殺し手が居る。

| 変異 | 殺し手 |
| --- | --- |
| 段 2（シリアルで絞る）を落とす | `I-S2` `U-C3` **`U-C6`** `U-C9` |
| 署名の確認を落とす | `I-B6` `I-N5` `I-S7` `I-S8` `U-S4` `U-S5` `U-S6` |
| 告知を操作の後へ動かす | `I-A2` `I-A3` **`I-A5`** |
| `verify_card` を呼ばない | `I-B6`（1 件） |
| `.conf` を親で source する | 16 件（**`U-L11`**） |
| 実パスでなく文字列で比較 | `U-L10` |
| 曖昧なとき最初の 1 枚を選ぶ | `I-N3` `I-S1` **`U-C7`** |
| 名前の先頭ハイフンを許す | `U-N2` |
| シリアルのバイト順を入れ替え | 27 件 |
| 暗黙 `default` を `hdd/default` へ | **`I-B2`** |
| `OFFSET` の形を見ない | `U-L12` |
| `SERIAL` の書式を見ない | `U-L13` |
| 区切り文字の混入を見ない | `U-L14` |

**帰属を取って試験の弱点が 2 つ出た。** `I-A5` は針を「カード名」にしていたため
`cmd_pull` の別の行に当たって順序を見ていなかった。シリアル漏れの欠陥には殺し手が
居なかった（`U-L2` は 1 枚しか置かないので漏れる元が無い）ので `U-L11` を足した。

簡素化（`verify_card` へ空の一覧を渡す・段 2 で名前を集める）の前後で、
触った箇所の変異の殺し手が**同一**であることを確かめてある。

`verify_card` の殺し手が 1 件だけなのは欠陥ではない。`-c` 経路（`select_card` の
中で既に照合済み）と自動経路（段 2 で絞り済み）では冗長で、暗黙 `default` だけが
唯一の担当経路だから。

## 何を試験しないか

- **実機の SD カード 2 枚での動作。** Mac 側は作ったイメージで張る。実物での確認は
  仕様の受け入れ基準 F1・F2（利用者の作業）。特に **F2「わざと間違える」** —
  カード A を挿して `-c B` を指定し、何も起きないことを見る。
- **エラー文面の「対処が実際に効くか」。** 自然文の正しさは機械オラクルを持たない。
  機械で押さえるのは ①必要な字句（カード名・シリアル・パス）が現れる
  ②`E1`〜`E9` の文面が互いに異なる の 2 点だけ。残りは人手レビューの項目。
- **同時実行。** 仕様で非対象。
- **`mformat` の挙動そのもの。** ハーネスの道具であって被試験対象ではない。
  ただし前提検査 `H2`〜`H4` が「期待どおりのイメージを作れたか」を毎回見る。
